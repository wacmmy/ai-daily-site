今日要点
OpenAI 公开为 monorepo 打造的 Git 兼容后端 Pando：中位 push 延迟降约 80%、日均近 1PB Git 流量，约 10 周用 Codex 做出并已服务生产；Tibo 转发「懂点 Git-fu」。Tibo 另预告 dots 将扩接入 GPT-6 Astra、GPT-6.1 Terra 等，并按任务选模。Guillermo 主张无状态沙箱不是正确基准（agent 要带走工作区），并力挺 WebMCP。Capy 0.7 Captains/Issues 正式 GA。Aaron Levie 称大量岗位将变成「管一队 agent」。Thariq 用一周后认为 200 美元档已够用，且智能只会越来越便宜。

OpenAI / Tibo（Codex）
1. OpenAI 工程博客《Scaling Git at OpenAI》公开 Pando：为 Codex 带来的高并发 push/fetch 打造的 Git 兼容后端，工程师与 agent 用法不变。中位 push 延迟降约 80%（近 5 倍），日均近 1PB Git 数据；分支级并行写、跨客户端复用 packfile、区域缓存。核心由一名工程师设计、Codex agent 团队实现，约 10 周从启动到生产（4 月起承载流量）；不打算开源后端，但已向上游回馈部分 Git 修复，并维护公开 patch tracker。Tibo 转发：「We know some Git-fu」，并点名 @tnm 团队。

Guillermo Rauch（Vercel）
3. 沙箱与 WebMCP 两条产品线进展：① 无状态沙箱是错误基准——agent 只有带着工作区（身份、skills、仓库、记忆）才有用；Vercel Sandbox 团队在保可靠与安全的同时兑现延迟/吞吐 SLO；Sandbox with Drives 创建中位从 1.7s→0.7s（约 2.4 倍）、p95 2.2s→1.6s，无需升 SDK。② 对 ctatedev 的 wterm WebMCP 支持力挺「So bullish on WebMCP」：agent 可 list/read/type/按键操作页面终端，按终端 opt-in、可读只读模式，无需 DOM 刮取或假按键。另：Vercel 构建会自动拦截已知恶意 npm 包安装脚本；Vercel MCP 在支持 MCP Apps 的客户端里以交互卡片展示部署状态与构建日志。

Garry Tan / Capy
4. Capy 0.7.0：Captains 与 Issues 正式 GA（无需开关）。Captains = 持久 agent，可跨设备编排上百条线程；Issues 支持筛选、全文搜索、标签、截止日期；Dock CLI 可在任意 Linux/macOS/Windows 无头跑 Capy。Garry 称 Captains 让他修 issue 的吞吐一夜约提升 5 倍，「跨 captain 与子线程协调是巨大解锁」。

Aaron Levie
5. 大量岗位（不只写代码）的新岗位描述：从「agent 帮你把活做快一点」转向「你帮 agent 把活干完」——人变成一队 agent 的管理者，而不再是带一点 AI 杠杆的个人贡献者。冲击最大的是信息密集工作（编程、安全、法律、生物、工程等）。杠杆开始与「工时→产出」脱钩，因为 agent 可并行；更早发现并按此改组织运作的人与公司会有复利优势。
