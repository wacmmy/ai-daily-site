Peter Yang：访谈 Claude Design 设计师 Nate Parrott，讲如何避开 Claude 的固定视觉偏好
1. Peter Yang（@petergyang）发布新一期访谈，嘉宾是 Anthropic 设计师 Nate Parrott，文字介绍里写他是 Claude Design 的设计者，并参与过 Artifacts 等。Nate 在节目里演示自己如何设计 Claude 新功能、做实时看板和动态制品，以及如何避开「AI 设计味」。Peter 在帖子里转述了几段原话：Claude「并不知道自己的设计偏好」；在它看来，「这件事自己只做过一次，所以觉得这套视觉完全是原创」。Nate 举例：它常会走到衬线字体、米白背景、橙色，以及卡片边缘的条。他们在 Claude Design 的提示里会写明：就这个模型而言，你容易过度偏向这两种字体和颜色，除非用户要求，否则不要用——「这样往往很有用」。他还说，传统设计强调少给用户增加摩擦，但做 Claude Design 时发现「问多少问题都不嫌多，人们就是喜欢这样」。好的设计师会问：我们在解决什么问题、人们已经熟悉哪些界面；同样的问题也可以拿去问 Claude。有时他会先从线框开始，免得 Claude 一头扎进字体和颜色。被问到现在能快速出原型、当设计师是不是更有意思时，Nate 说自己有工程背景，在 The Browser Company 做 Arc 时，一个想法常常要花几周才能做出来看效果，光是预研就花了一年；现在在 Anthropic，这个周期可以压缩到一两天，但「放进别人手里、看他们会不会用」这一段并没有被压缩。节目视频在 YouTube；文字版在他的 newsletter，页面标注为付费内容；他也给了 Spotify 的收听入口。
背景：这是一期新访谈，不是 Claude Design 的产品发布。近 7 天 Builders 简报没有报过 Nate 或这套「先告诉模型它自己的视觉偏好」的做法。
实际影响：要用 Claude 做界面的人，可以把「不要默认走衬线、米白、橙色和卡片边条，除非我要求」写进 design.md 或设计提示，并先从线框对齐流程；完整演示在节目视频里，文字版需付费。

Dan Shipper：把每日改稿做成会复利的 skill，四个模型在摘要检查上提升二十多个百分点
2. Dan Shipper（@danshipper）发帖：他们最近在做 compounding skills（每次使用都会变好的 skill），认为 @hammer_mt 把方法跑通了。他周末做了一个帮助写《Context Window》摘要的 skill，用 autoresearch 迭代，直到相对无 skill 基线达到他自己口味的约 80%。完整实验写在 Every Frontier，标题是《Turn your daily newsletter edits into AI checks—and watch every frontier model jump 25+ points》。做法是：不再把改稿意见留在聊天记录里，而是把真实草稿、他真正想发出去的「金标准」版本，以及具体反馈，存进 Every Checks；每次指出问题，就变成一条能否打分的对错检查，例如开头有没有说明在纠正什么、为什么读者会想做这个测试，有没有避开「编排一群没有面孔的子 agent」这类内部黑话。8 个真实案例一共抽出 74 条检查。他们据此做了可复用的 `short-idea-summary` skill，从 v1 优化到 v9；每个版本在隔离、零上下文的沙箱里，用四个前沿模型（Gemini 4 Hydrogen、Claude Opus 5.5、GPT-6 Astra、Claude Sonnet 5.5，均为 High effort）测试，并由 `claude-sonnet-5-5` 对这 74 条做盲评。v1 在最初 7 个案例上，各模型只有 34%–56%（Opus 5.5 为 56%，GPT-6 Astra 为 46%，Hydrogen 为 40%，Sonnet 5.5 为 34%）；到 v9，在全部 74 条检查上，Hydrogen 为 60/74（81.1%），Opus 5.5 与 GPT-6 Astra 均为 58/74（78.4%），Sonnet 5.5 为 56/74（75.7%）。文章的结论是：想让模型稳定贴近你的口味，先收集你会真正发出去的金标准例子，再把差距写成自动打分的检查，然后系统优化 skill。
背景：昨日简报已报过他把 iPhone 录屏交给 agent，以及 Every Frontier 这条实验流；本期新的是同一条 feed 上、把每日改稿沉淀成检查集和可复用 skill 的一次完整实验，不是录屏工作流的再预告。
实际影响：做固定体裁写作或摘要的人，可以按「金标准例子 → 对错检查 → 迭代 skill」这条回路来做；数字和检查例子以实验页为准。

Guillermo：两次提示做出纯 Web Components 的 Winamp 播放器，复用了 14 项 UI SDK 行为
4. Guillermo Rauch（@rauchg）发帖说体验到了 @uisdk 的效果：只用两次 fx + Gemini Argon 的提示，做出纯 Web Components、没有框架的界面。他写 agent 开箱即用复用了 14 项 UI SDK 行为：窗口缩放、拖拽、菜单栏悬停切换、typeahead、工具栏的 roving focus、10 段均衡器滑块、作用域内快捷键、ARIA，以及 WebMCP 的 agent 控制。演示站点是一个 Winamp 风格播放器 https://winamp-ui-sdk.vercel.app/ ，音乐来自 Suno。
背景：11 月 13 日简报已经报过 Vercel 推出给 agent 用的 UI SDK（行为库，当时是 beta）。本期新的是他用 fx 和 Gemini Argon 做出来的一个可打开的演示，并列出了实际被复用的行为，不是 SDK 发布的再预告。
实际影响：想看 UI SDK 在无框架 Web Components 里长什么样的人，可以直接打开这个演示；SDK 本身的安装和 skill 仍以 11 月 13 日给出的 ui-sdk.dev 和文档为准。
