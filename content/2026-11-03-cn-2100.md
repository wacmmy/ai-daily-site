今日要点：DeepSeek Harness于11月2日晚公开创造模式的演示和7组提示词，11月3日发布v0.2.2-alpha.3，文件修改的先读防护改为默认关闭。字节Seed公开GenFirst训练代码，权重仍限非商业。MiniMax放出BYOB Table协议，并把驱动本机MiniMax Code的Python SDK发到0.1.0b1。

DeepSeek
公开创造模式演示，用对话编写并安装插件
11月2日晚，DeepSeek Harness官方账号发出创造模式的演示，宣传语是把想法变成可以使用的插件，并公开视频里7个插件的中英文提示词。产品页写明，可以安装现有插件，或在创造模式里通过对话创建插件，用来扩展工具、技能和界面。官方演示里，一句「帮我写一个番茄时钟插件」用时5分24秒，完成编写、安装和验证。7个演示包括地标3D画廊、Transformer内部计算的3D演示、五种视觉风格切换、海报工作台、视频剪辑工作台、论文阅读器和会话用量统计。合集页提醒，部分插件经过多轮打磨，单条提示词不一定能复现视频效果。这次没有新模型，也没有新价格。
背景：官方说明里，创造模式不是新模型，而是一种预设：具备标准模式的能力，并带有运行时检查、插件实验和预设创作指导。
实际影响：把提示词贴进Harness并选择创造模式即可尝试生成插件。单条提示词不一定得到视频里的效果，可以继续用对话修改。
来源：https://www.deepseek.com/zh/harness/
中文报道：https://original.ifeng.com/c/8xk4PQk0VoF

发布Harness v0.2.2-alpha.3，文件修改防护默认关闭
11月3日15时56分，DeepSeek发布Harness v0.2.2-alpha.3。文件修改的先读检查和外部修改防护改为默认关闭，沙箱限制和Review保持不变，需要原来那套防护的profile可以显式恢复。实验性的「变更请求与工作树」把代码审查和工作树收进同一入口，可通过可搜索的文件树查看本地和拉取请求的差异，把选中代码和评论交给Agent。此前单独启用「Git工作树」插件的用户，要手动从profile的dsh.profile.bundles里移除@deepseek-ai/dsh-experimental-tool-worktree。同版新增默认关闭的apply_patch，可一次完成多文件的新增、编辑、删除和移动。自动化任务改为宿主级管理，可以手动创建、直接编辑，或用预填提示在会话里创建。
背景：上一份同通道版本是10月28日的v0.2.2-alpha.2，10月30日另有v0.2.1-rc.5。
实际影响：升级后，默认不再要求先读文件再改，也不再默认拦截外部修改。用过独立Git工作树插件的profile，不移除旧包会和合并后的入口叠在一起。
来源：https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.3

字节豆包
公开GenFirst训练代码，权重仍限非商业
11月3日14时42分，字节Seed的GenFirst仓库写入首份代码，许可为MIT。这是论文《GenFirst: Generation Before Reconstruction for Stable End-to-End Latent Generative Modeling》的PyTorch实现，包含端到端VAE与SiT训练、随后的解码器微调，以及在冻结VAE上训练先验，另有文生图、共享隐空间和文本-图像联合建模的配置。仓库写明只包含扩散先验的EiT版本，自回归的EAR没有放出。README列出的作者结果是：ImageNet-256上使用CFG的gFID为0.97，文生图GenEval为0.90。
背景：论文于8月29日提交arXiv（2608.29335）。Hugging Face上的权重创建于10月29日，许可为CC BY-NC 4.0。这次新的是训练和评测代码。
实际影响：代码可以按MIT使用。下载的权重只能用于非商业研究。要复现端到端训练可以用仓库里的SiT脚本，自回归版本不在其中。
来源：https://github.com/ByteDance-Seed/GenFirst
来源：https://huggingface.co/ByteDance-Seed/GenFirst

MiniMax
公开BYOB Table协议，多个代理可以坐到同一张桌
11月3日20时29分，MiniMax在GitHub新建mcode-agent-table，放出BYOB Table Protocol v0.1和TypeScript参考实现。每个人把自己的代理带到共享桌上，可以是MiniMax Code、任何支持MCP的代理，或一段脚本。代理保留自己的记忆、身份和权限，桌子不拥有代理。桌子维护只追加的账本。规则是：代理提议，受影响的所有者批准，再由该所有者自己的代理执行，另一个席位核验。需要Node.js 22.19或更高版本。用真实模型做演示时，本机要有0.6.3以上的mcode和MiniMax API密钥。
背景：仓库在这一天新建，协议版本是byob/0.1。
实际影响：跨所有者的改动不会由别人的代理直接落地，要本人签名批准后，才由自己的代理执行。
来源：https://github.com/MiniMax-AI/mcode-agent-table

Python SDK 0.1.0b1公测，用来驱动本机MiniMax Code
11月3日12时45分，minimax-code-sdk 0.1.0b1上传到PyPI。仓库说明这是首个公开测试版，通过本机的mcode命令行驱动MiniMax Code：每一轮执行mcode exec，并用同一个会话继续。需要Python 3.10或更高版本，以及0.6.3或更新的mcode。在0.1.0正式版之前，安装要加--pre，或直接指定0.1.0b1。导入名是minimax_code。会话属于创建时的工作目录，换一个目录去续跑会失败，重试也不会成功。
实际影响：安装命令是pip install --pre minimax-code-sdk。续跑必须使用创建会话时的同一工作目录。
来源：https://pypi.org/project/minimax-code-sdk/0.1.0b1/
仓库：https://github.com/MiniMax-AI/minimax-code/tree/main/packages/code-sdk-python
