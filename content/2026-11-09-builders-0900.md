Garry：公开 GHarnessEvals，目前分不出谁更聪明、成本和速度差得大
3. Garry Tan 说自己在做「固定前沿模型、只换 harness」的开源评测，并贴出目前结论。仓库 GHarnessEvals 写明：固定 Opus 5.5 或 GPT-6.1 Sol 与任务，只换系统提示、工具和记忆，看通过率、每解一题的成本和耗时。他贴图总结：7 套组合跑同一批 20 道公开编程题，通过率都在 71%–79%（Opus 上是 Claude Code、OpenClaw、Hermes、QM；Sol 上是 Codex、OpenClaw、Hermes），两两比都「分不出来」，因为 20 题里有 14 题在每套组合上得分相同——他认为这是题目太容易，不是打成平手；更难的 Terminal-Bench 重跑当时还在进行（编号 GST-1805）。成本差得大：Opus 上 OpenClaw 每解一题约 0.44 美元、Claude Code 0.22 美元、Hermes 0.24 美元、QM 0.19 美元；OpenClaw 也最慢，每轮中位约 99 秒，Claude Code 约 40 秒。Sol 上 Codex 最便宜也最快，每解一题约 0.17 美元。他的现阶段建议是按成本和速度选：Opus 用 Claude Code，Sol 用 Codex。仓库注明这是公开题上的开发结果、不是留出验证集；Claude Code 与 Codex 不能跑同一模型，因此两者不直接对比。他还披露 gstack、gbrain 是自己的项目，QM 是他执掌的 Y Combinator 的项目，YC 也投资了 Hermes。Tibo 回复感谢他跑评测并公开。
背景：社区常把「换个 harness 就能明显变聪明」当成经验；他这次把模型钉死，只看 harness 本身。
实际影响：在这批偏容易的公开题上，先别指望靠换 harness 拉开通过率；若以他现在的数字做选型，Opus 侧更看 Claude Code 的成本和速度，Sol 侧更看 Codex。更难的 Terminal-Bench 结果当时还没出来。

Guillermo：WebGL2 黑胶唱机物理模拟
4. Guillermo Rauch 用 WebGL2 和 Web Audio 做了一个黑胶唱机物理模拟，称「准得惊人」。站点是 vinyl-gl.vercel.app：不是直接播歌曲，而是把歌曲转成沟槽的物理形状，模拟唱针每秒贴着槽壁走 384,000 次，再把这种运动会在唱头里感应出的电压变成你听到的声音。所以爆音、噼啪、wow/flutter 和内圈变闷，都是模拟的自然产物；也可以「打碟」。他写所用歌曲是公有领域或 CC 授权，并说代码已附上供 remix 和重新部署。
背景：这是他做的交互演示，不是 Vercel 产品发布。
实际影响：想看浏览器里能把物理模拟做到哪一步，或想改一道自己部署，可以直接打开站点和他附的代码。

Aaron Levie：每 3–6 个月重试一遍旧题；产出上限正在被掀开
5. Aaron Levie 写：AI 里一条好经验是每隔 3 到 6 个月回头试一遍以前做不到的事，看现在行不行；他认为眼下比历史上任何时候都更适用。过去半年在计算机使用和工具调用、更少的上下文腐烂、更好的推理、多模态，以及若干关键领域的更深专业能力上，模型能独立执行的事情已经大不一样。这意味着不再只靠模型从零生成一切，它们可以很好地调用现有系统（或专门为它们做的新系统）。他举例：安全 agent 用已有数据源和网络工具、IT agent 跨软件栈跑流程、数据 agent 做迁移、设计和建筑 agent 用 CAD。他另发帖（引用 Greg Brockman「前沿模型加大测试时计算，正在成为科学发现的引擎」）说：我们正从「产出大致跟你和 AI 来回聊的速度绑定」，进入「丢一个问题给一队 agent，让它们去干任意体量的活」——生产率提升可能从大约 20%–50%，变成没有明显上限。编码领域已经看到；接下来网络安全几乎是「更多 agent 审查更多东西就会明显更好」的问题，科学和生命科学也在出现同样趋势。任何能把计算机工作并行化的领域都会如此。
背景：他一直在讲会用 agent 的人和还按旧方式工作的人之间的产出差距；本期把时间尺度（每隔几个月重试）和形态变化（从对话节奏变成可并行的 agent 群）说得更具体。
实际影响：几个月前试砸的计算机使用、跨系统工作流或科研任务，现在值得再跑一遍；规划时可以把「派一队 agent 并行干完」当成一种新默认，而不只是把聊天机器人做得更勤快。
