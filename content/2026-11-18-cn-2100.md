DeepSeek
Harness升到0.2.2-rc.5，DeepSeek模型的搜索不按次收费
11月18日20:51，DeepSeek发布Harness v0.2.2-rc.5。DeepSeek模型改为使用DeepSeek服务端搜索，搜索不按次收费；其他模型仍默认使用DeepSeek Search API。同一天01:53的rc.4修了两处：模型请求收到异常消息时的表现，以及桌面端LiveShare无法创建分享。
背景：11月13日的rc.3加入了会话导入。11月11日的rc.2把网页搜索默认改成DeepSeek Search。11月13日开放的Search API是每1000次5元。这次新的是，Harness里用DeepSeek模型时，搜索不再按次收费。
实际影响：升到rc.5后，用DeepSeek模型的搜索不再按次计费；用其他模型时仍默认走DeepSeek Search API。桌面端之前建不了LiveShare的，rc.4已经修了。

智谱 GLM
Unity插件更新到0.1.6，不再执行项目内同名命令
11月17日23:26，智谱把ZCode的Unity插件从0.1.5升到0.1.6。环境检查解析命令时，只在绝对路径的PATH目录里找，不再执行项目目录里的同名程序，经符号链接指回项目内的也不执行；相对的PATH项会被忽略。显式传入、指向项目内部的路径同样拒绝。Windows上只认.com和.exe，不选.cmd和.bat。
背景：工单号是ZP-20261111-16。注释写明，Windows上裸命令会先在工作目录，也就是用户项目里查找。
实际影响：检查Unity环境时，不会跑到工程目录里碰巧同名的程序，要执行的是PATH里解析出的绝对路径。不选.cmd和.bat，是因为新版Node不经shell就会拒绝它们，选中会把找得到的命令报成找不到。
来源：https://github.com/zai-org/zcode-plugins/commit/bd10336dd

月之暗面 Kimi
Kimi Code 2.6.3发布，前台命令和停止钩子修复
11月17日23:15，月之暗面发布Kimi Code 2.6.3。前台Shell命令不再重复输出，加载状态会消失。每轮回复完成后，外部Stop钩子会执行。恢复或创建会话分支时，后台任务通知不再意外触发新回复。后台通知不再把Tower任务意外停掉。Windows上WebBridge守护进程在运行时可以更新。同一版还写了修复若干已知问题，说明没有逐条列出。
背景：11月14日的2.6.2给自定义模型网关加了搜索和反馈地址。
实际影响：升级到2.6.3后，前台命令不应再刷两遍输出并一直转圈。依赖外部Stop钩子的，每轮结束会被调用。开着后台任务时切分支，不应再自己多一轮回复，也不应把Tower任务停掉。
来源：https://github.com/MoonshotAI/kimi-code/releases/tag/@moonshot-ai/kimi-code@2.6.3

腾讯混元
Hy4 flash开放权重，含指令版、FP8和Base
11月18日，腾讯混元开放Hy4 flash权重。GitHub在12:24更新，IT之家12:36报道。三份权重都在Hugging Face、ModelScope和GitCode：指令版Hy4 flash、FP8量化版、预训练的Hy4 flash-base。Base不是对话模型。开源说明写总参数220B，其中不含Engram、视觉编码器和DFly2的是155.5B，Engram 63.5B，视觉编码器0.43B，DFly2 0.85B。文本每个token激活11.3B，视觉另计0.43B。上下文100万（1,048,576）token，输入文字和图片，输出文字。指令版的reasoning_effort默认high，也可设no_think。
背景：11月16日已经在腾讯云TokenHub、WorkBuddy、元宝、企业微信、QQ、ima、Marvis上线，当时写总参数224B、激活12B，并说计划开源。这次新的是权重可以下载。Hugging Face上三个仓库在11月17日11:44建立，11月18日12:24更新。
实际影响：当前transformers正式版还不能直接加载，要按文档安装指定提交。生产部署文档推荐vLLM镜像vllm/vllm-openai:hy4-flash，或SGLang镜像lmsysorg/sglang:hy4-flash，示例用FP8、8卡。另有微调指南。GGUF在AngelSlim，说明写是供端到端测试。许可是Tencent Hy License，不是Apache 2.0。把模型做成给第三方远程调用的推理或微调服务，若全球连续12个月总收入超过5000万美元，或产品月活超过1亿，要另外取得书面许可；只在内部用、不把模型、衍生模型和输出给第三方，则不受这一条限制。不含通用模型接口、只做特定功能的终端产品，以及只是转发到别人运营的模型服务，不算这里的MaaS。联系邮箱是hy_partners@tencent.com。API目录价和11月30日12:00前的五折，开源说明没有改。

MiniMax
画布小应用上线DeepSeek会话导入
11月18日20:31，MiniMax Code的小应用仓库加入DeepSeek会话迁移。它读取DeepSeek网页版设置里的数据导出文件，在MiniMax Code里建成一个名为DeepSeek的项目，会话出现在侧栏，可以接着聊。导入器直接写~/.minimax下的存储，因为小应用接口不能从历史创建用户看得见的会话。写入前会核对表、列和列式版本，对不上就拒绝。
背景：11月13日DeepSeek Harness的rc.3也能把App或网页历史导入自己的工作区。这次是导入到MiniMax Code。
实际影响：作者写明在Windows 11、MiniMax Code 3.1.11上测过，但没有拿一份真实的当前数据目录跑过。宿主存储结构一对不上，导入会拒绝写入。
来源：https://github.com/MiniMax-AI/MiniMax-Code-MiniApps/pull/144

画布1.22.10修复首尾帧被拒
11月18日17:57，画布小应用升到1.22.10。带last_frame_image的请求里，input_image必须声明成first_frame或不声明，否则厂商拒单。原先首尾帧会把input_image也声明成last_frame。现在只有末帧那一种声明last_frame，其余声明first_frame。
背景：11月12日画布加入视频生成，11月13日可以指定时长和画幅。这次是首尾帧不再被拒。
实际影响：只影响H3和H3-Max的首尾帧。首帧、末帧和参考图集合的字段没改。厂商拒单原文是：reference inputs last_frame_image requires reference_type first_frame or omitted。
来源：https://github.com/MiniMax-AI/MiniMax-Code-MiniApps/pull/143

章鱼娘1.10.0更新，默认关闭跨会话采集
11月18日17:57，MiniMax Code小应用MMX章鱼娘升到1.10.0。跨会话感知默认关闭。关掉时不再订阅会话，不再把其他会话的标题和运行状态送进提示词，已经显示的跨会话内容会清掉。升级时，旧版本里默认打开的状态会被重置为关，除非用户在面板里手动打开过开关。
背景：插件说明写，它声明了session.read，用来读每个对话每轮的最终回复、标题和运行状态，判断Agent在思考还是已经完成。1.9.0及更早没有“用户打开过”的标记，保存的开启值不能当成用户同意。
实际影响：更新后，想让章鱼娘反映其他会话，要在面板里手动打开「她知道我在忙什么」。不打开就不采集。她自己的对话历史仍只在本机。
