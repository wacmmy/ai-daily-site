DeepSeek
Harness 发布 0.2.3-alpha.3
11月28日20:36发布。语音输入改为 DeepSeek 云端识别。新增实验性语音朗读插件，可以用 DeepSeek 语音合成朗读已经完成的助手回复。新增实验性 Office 桌面原生预览，可在侧栏或浮窗里预览文档、缩放和选取，也可以全屏放映幻灯片。新增实验性即时通讯插件，可在群聊和私聊里向智能体发任务并接收回复。插件管理页新增「连接器」标签，用来管理官方连接器，以及添加和测试自定义 MCP 服务器。文件编辑改为 apply_patch。
背景：11月22日的 alpha.2 把 Node.js 下限改为 24.x 的 24.22.3 或 26.13.1。这次是同一条 0.2.3 上的功能更新。
实际影响：要云端语音识别、朗读、Office 预览或即时通讯，需要装这个 alpha。自定义插件如果还在用旧的工具执行器，要改到新的 Native/PTC 注册表。Web 和桌面客户端升到 React 19。
来源：https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.3-alpha.3

补报：灰度显示每轮对话的估算费用
IT之家 11月27日8:21报道，昨日起，部分用户在网页端和移动端完成一轮对话后会看到详情页，列出本轮 token 数量和按 API 价格估算的金额。个人对话仍然免费。用户截图按空闲时段计价：输入缓存命中 0.02 元/百万 tokens，缓存未命中 1 元/百万 tokens，输出 4 元/百万 tokens。详情页底部有一行「截止到本轮，上下文已占用」。官方 API 更新日志最近一条仍是 11月13日，没有这条功能。
实际影响：被灰度到的人能看到估算费用和上下文占用。页面上的金额是估算，不是扣款。

补报：豆包工作接入剪映官方插件
IT之家 11月27日10:33报道，当天上午豆包官方宣布，豆包工作独家接入剪映官方插件。用户把视频素材交给豆包工作，用一句话描述需求，由它调用剪映完成剪辑，之后可以继续用对话修改，或打开剪映多轨草稿细调。口播场景包括删减重复、处理读错、添加字幕和调整字幕字体字号。也可以一句话调用剪映 Hub，把文稿、代码、脚本或商品图转成科普动画、知识短视频、短漫剧或营销短片。入口在豆包工作电脑端侧栏「插件」，搜索「剪映」。需要从剪映官网下载的最新版客户端。近期首次接入并完成登录的用户，有机会获得 200 剪映积分，以产品界面为准。
实际影响：电脑端装上官网最新版剪映后，可以在对话里调用剪辑。积分是否到账以界面显示为准。

MiniMax
补报：苹果下架 Talkie
11月26日，苹果在全球 App Store 下架 MiniMax 的 Talkie。财新 11月27日14:09报道，下架原因是被指控带有色情内容。稿件引 11月25日澳大利亚广播公司与 The Bureau of Investigative Journalism 的调查：有家长发现 AI 生成角色向未成年人发送色情化信息。苹果和谷歌商店的年龄限制都写着 18 岁以上，调查称年龄核验宽松。谷歌应用商店没有下架。MiniMax 没有回复财新的置评请求。
背景：财新标题下写，此前该应用被 OpenRouter 移除「零数据保留」标签。稿件没有写这件事的日期。
实际影响：App Store 里已经没有 Talkie。谷歌应用商店仍可下载。
来源：https://www.caixin.com/2026-11-27/102509252.html

公众号图文工作台升到 1.1.0
11月27日22:20合并，版本从 1.0.0 改为 1.1.0。发布参数改为按检测到的接口自己声明的字段来填。正文默认仍是带样式的 HTML；如果接口把图片分开传，或 HTML 超过接口声明的长度上限，就改发纯文本，并在正文里逐行列出插件数据目录内的图片路径。复制正文改为复制这份纯文本。封面和每张插图可以按当前要求单独重画。接口如果要一份草稿里没有的字段，例如只有后台才知道的草稿 id，页面不会发起调用，并写明缺哪个参数。
背景：昨日简报的 1.0.0 在没接上公众号接口时，两个发布按钮保持不可用。
实际影响：接上接口并选中一个之后，才会按该接口的字段组参数。作者写参数对照过已连接接口的实时结构，但没有真正发出一篇公众号，也没有读回发布结果码。最低客户端仍是 MiniMax Code 3.1.6。测过的环境是 MiniMax Code 3.1.19 的 Windows 11。
来源：https://github.com/MiniMax-AI/MiniMax-Code-MiniApps/pull/171

FactScribe 升到 1.3.0
11月28日13:18合并，版本从 1.2.0 改为 1.3.0。往 CRLF 稿件里插入 AI 草稿时，草稿块改用这份稿件的主要换行，不再留下单独的 LF。段落级页面可以添加和删除引用、预览图片、安装示例论文。判断本机 Python 是否可用时，改为等标准输出读完再下结论。
背景：昨日的 1.2.0 让 Windows 上 CRLF 稿件可以按页面指纹保存。1.2.0 插入 AI 草稿时仍把草稿块写成 LF。
实际影响：CRLF 稿件里新插入的 AI 草稿也是 CRLF，原稿换行不被改掉。作者写没有在真实 Windows 主机或 Linux 上做端到端复测。
来源：https://github.com/MiniMax-AI/MiniMax-Code-MiniApps/pull/174

桌宠升到 0.9.4
11月28日13:17合并，版本改为 0.9.4。点击「放到桌面」后，如果宠物落在屏幕外面，按窗口实际所在屏幕的工作区把位置校正回来，并记住修正后的坐标。本来就在可见区域内的副屏位置保持不动。
背景：昨日的 0.9.3 修的是展开任务卡后连续拖动时窗口越拖越大。
实际影响：弹出的桌宠会落在屏幕工作区里。作者写在 Windows 11、MiniMax Code 3.1.19.232、显示缩放 150% 上测过，没有在真实副屏、拔插显示器、不同 DPI 或 macOS 上复测。
来源：https://github.com/MiniMax-AI/MiniMax-Code-MiniApps/pull/166

小米 MiMo
MiMo-Code 发布 0.1.18
11月27日23:16发布。Skill 改为动态发现：新增或修改之后不用重启，新旧会话都会看到变化，斜杠命令列表也不再等待 MCP 启动。读取媒体从通用 read 拆成 read_image、read_audio、read_video，TUI 按媒体类型显示。同时修复重复传入 --model 会报错、代理或软链接缓存下插件安装失败、auth.json 里有非字符串元数据时凭据被丢掉，以及 OpenAI Responses 无状态请求里推理块被拆开。
实际影响：改 skill 不用重启客户端。图片、音频和视频不再走原来的 read。
来源：https://github.com/XiaomiMiMo/MiMo-Code/releases/tag/v0.1.18
