DeepSeek
Harness v0.2.2-rc.3发布，可导入DeepSeek历史会话
11月13日15:56，DeepSeek发布Harness v0.2.2-rc.3。新增实验性「DeepSeek 会话导入」插件，可以把DeepSeek App或网页版的历史会话导入工作区，并继续对话。同一版修复Windows桌面版应用内更新可能失败、更新后无法自动重新打开的问题。
背景：11月11日的rc.2把网页搜索默认改成DeepSeek Search。这次是0.2.2的第三个候选版。
实际影响：要接着旧会话，需要安装这个实验插件。Windows上应用内更新失败、或更新后打不开的，这次修了。
来源：https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.3

智谱 GLM
ZCode视频插件0.2.0可指定时长和画幅
11月13日13:43，智谱把video-generation升到0.2.0。generate_video可以传duration和ratio。时长是4到30的整数秒，或-1由模型决定，不传默认4秒。画幅可以是16:9、4:3、1:1、3:4、9:16、21:9或adaptive，不传默认16:9。用了first_frame时画幅跟随首帧，ratio只能不传或传adaptive。
背景：11月12日的0.1.0里，时长、画幅、模型和水印都由服务端固定。
实际影响：模型、分辨率和水印仍由服务端固定。时长越长，耗时和额度消耗越多。安装或更新后要新建会话。
来源：https://github.com/zai-org/zcode-plugins

ZCode开源仓库同步到v3.18.2，国内未关联账号可用BigModel Start
11月13日16:21，ZCode开源仓库同步到v3.18.2。登录文档把一条修正记在11月12日：国内入口（zai_cn）的Start固定属于BigModel。从未注册BigModel、profile里没有关联块的国内账号，可以用ZCode主体和共享JWT查询、领取并使用BigModel Start。Z.ai Start对这类账号不可用。个人和团队套餐、官方MCP和额度重置仍要有直登或关联材料。同一版里，Linux桌面在首次读凭据时，如果系统钥匙串打不开、并且目录还没有绑定凭据来源，会改用权限0600的私有文件密钥；已经绑定来源的目录不会切换。
背景：修正前，这类新账号两个Start都被判成未连接，设置页出现两个Start入口，不查余额，模型也不能执行。v3.17.2的国内入口是BigModel直登，登录就能确定家族。
实际影响：只登录了国内入口、没有BigModel关联的账号，现在可以领取并使用BigModel的Start体验套餐。Linux上钥匙串不可用、且还没存过凭据的桌面，会落到本机私有文件密钥。
来源：https://github.com/zai-org/ZCode

月之暗面 Kimi
Kimi Code 2.6.1发布，长会话重开和压缩两处修复
11月13日15:11，月之暗面发布Kimi Code 2.6.1。重新打开长会话时，不再出现长达数秒的加载。长会话在工具结果带有注释、错误或计时头时，不再停在空回复上、也不再因此跳过压缩。

腾讯混元
发布实时语音模型Hy Realtime，元宝通话可选初语
11月13日，腾讯混元发布实时语音模型Hy Realtime。官方称它对口齿含糊、话说半截和中途改口，可以结合上下文还原意图。工具调用上，它按对话上下文判断是否联网搜索，把搜索决策、调用工具和生成回答放在一起。唱歌与腾讯音乐TME灵音AI团队合作：可以按歌手、专辑、曲风、语种、发行年份和热度组合点歌，也可以接着上文继续选。官方举例是「来首2010年到2020年之间的英文民谣」。模型已在元宝语音通话和腾讯客服上线，近期上线腾讯云并提供API。官方称下一步重点是双工交互、长期个性化记忆，以及前后台Agent交互。
背景：API这一步还没对外开放。
实际影响：当前要在最新版元宝App的语音通话里选择「初语」音色。网页上可以打开 https://rtcube.cloud.tencent.com/component/hunyuan/index.html 体验部分能力。开发者现在还不能调用API。
来源：https://www.ithome.com/1/026/825.htm
中文报道：https://www.yicai.com/news/103440081.html

MemHub 1.0.7发布，图谱损坏会隔离重建，备份带上记忆
11月12日，MemHub记为1.0.7，构建号48，底层仍是hy-memory 2.0.16，覆盖Linux x64/arm64 Runtime，以及macOS arm64的App和Runtime。构建号在当晚23:50写到48。Ultra遇到损坏的知识图谱时不再让Core无限重启：探测子进程有墙钟上限（60秒再加每MB 0.5秒，最多120秒）和2GB内存上限，失败就把图改名为graph.quarantined-加UTC时间，不删除，只留最新两份，然后按用户重建。界面用11种语言显示「知识图谱文件损坏，已自动重建」。memhub settings backends可以把ultra的图换成Neo4j或Memgraph、把向量换成Qdrant，默认仍是内置Kuzu加Chroma；切换不搬动已有记忆，库里已经有图时要显式采纳，FAISS和内置Qdrant会被拒绝。备份改成目录，带上管理库和各个SDK存储里的记忆；恢复对不上就回滚，跨后端恢复会被拒绝。agent_max_tokens可以设在512到32000，evolve和System 2的输出不再默认截在2000个token。OpenCode 2的新存储可以导入。Hermes和OpenCode的历史导入现在会写出记忆。
背景：11月12日简报写的是SDK 2.0.16的导出导入，以及可选的PostgreSQL。MemHub这次没有安装hy-memory的postgres附加组件，业务库仍是SQLite，MEMORY_BUSINESS_STORE不起作用。
实际影响：图谱文件坏了会被改名隔离并重建，不用一直重启。要换Neo4j、Memgraph或Qdrant，用memhub settings backends。memhub backup create会先显示体积，确认后才写入，备份里现在有记忆本身。
来源：https://github.com/Tencent-Hunyuan/Hy-Memory/blob/main/CHANGELOG.md

MiniMax
画布小应用1.22.9支持时间轴剪辑，参考图上限提到16张（补报）
11月12日19:46，MiniMax Code的画布小应用合并1.22.9。视频剪辑改成从文件抽出的帧和音频波形，两端可拖，范围落在素材内，并有走带、播放头和时间读数。视频卡可以分离音频，图片卡增加AI抠图和2倍超分，都走matrix连接器。超分要求长边不超过2048、短边至少256、文件不超过10MB，超限的图在请求发出前就被拒绝。图生图参考图上限从9张改为16张，图片模型标为MiniMax-H3-Image，默认4K、画幅自适应。音轨导出一律用mp3。页面不在时，运行时仍按原有的10秒节流向厂商查询进行中的任务。没有产出时不再报完成。上一期21:34未收录，这次补报。

小米 MiMo
MiMo Code v0.1.17发布，上下文和推理档改从模型配置读取
11月13日16:02，小米发布MiMo Code v0.1.17。上下文上限、输出上限和推理档位改从models.dev和用户配置读取，不再按模型名推断，默认也不再发送temperature和top_p。/variants可以在配置里按档位名启用，子agent继承父会话的档位。GPT模型不再自动换成Codex风格的提示词和工具集，所有模型默认用同一套；要打开就设MIMOCODE_CODEX_MODE=true。内置联网搜索改为MIMOCODE_ENABLE_EXA=1才启用，小米网关搜索已去掉，也可以改接搜索MCP。小米API key和Token Plan key可以同时登录。记忆搜索支持中文子串召回，并迁移已有索引。额度耗尽不再重试。压缩失败不再留下边界。云端会话分享和第三方上传已去掉。
背景：上一版是10月26日的v0.1.16。
实际影响：升级后，还在依赖按模型名自动限制上下文、或默认附带temperature和top_p的调用，行为会变。要Codex风格提示词就设置MIMOCODE_CODEX_MODE=true。要用内置联网搜索就设置MIMOCODE_ENABLE_EXA=1。云端分享入口没有了。
来源：https://github.com/XiaomiMiMo/MiMo-Code/releases/tag/v0.1.17
