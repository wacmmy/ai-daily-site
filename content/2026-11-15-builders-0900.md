Guillermo / fx：v0.0.17 上线子 agent，Token Pass 成为一等能力
1. fx 官方 changelog 发布 v0.0.17（标注日期 2026-11-14，二进制 6.33mib，15,854 项测试）。这一版让子 agent 可以和主 agent 一起干活、做完再汇报；你可以切到某个子 agent 去看它、给它发消息或回答它的提问；每个子 agent 可有自己的模型、effort、Fast 模式和权限模式，并且最多可以嵌套两层。Vercel Token Pass 成为一等能力：Token Pass 模型会排在模型选择器前面，`/credits` 和 `fx credits` 能看到额度及重置日期。工具定义比 0.0.16 缩小 48.0%，新会话的第一次请求缩小 32.4%；官方写在 9 个模型族的实际测试里，后续输入进提示缓存的比例从 61.3% 升到 82.0%。Guillermo Rauch（@rauchg）转发这次更新，称子 agent 用起来很顺手，并感叹 6.33mb 里装进了不少能力；他说自己的项目都是先用最强模型做规划，再把活派给更快的子 agent，这一条写在 `~/.fx/AGENTS.md` 里。
背景：11 月 12 日简报里，Guillermo 推荐过在 fx.sh 上免费试用 Reflection 的 Beam，那是模型和试用窗口；本期是 fx 这套本地/CLI agent 本身的一次版本更新。
实际影响：已经在用 fx 的人可以按官方 changelog 升到 0.0.17，直接试用子 agent，以及在有 Token Pass 的团队里用内置额度；文中缓存和体积数字来自官方对比测试，不能直接当成自己工作区里的保证。

Garry Tan：Fable 5.2 编码通过率接近 Opus 5.5，但每解出一题约贵 2.80 倍
2. Garry Tan（@garrytan）发帖建议：在 Claude Code 里把 Opus 5.5 继续当作编码默认模型。他在 Claude Code 2.1.322 上跑了 52 道编码任务，Fable 5.2 解出的数量和 Opus 5.5 差不多（82.7% 对 84.6%），但每解出一题的成本约是 Opus 的 2.80 倍。他还写：这些题 Opus 大多已经能解，要把两者分开，得用更难的题。完整报告放在他此前开源的 g-harness-evals 仓库里（报告目录日期为 2026-11-12，帖子发于 11 月 14 日 12:45，上海时间）。
背景：11 月 9 日简报已报过同一个 g-harness-evals 仓库，当时是把模型钉死、只比较不同 harness 的通过率和成本。昨日简报里，Peter Yang 分享的是 Fable 5.2 与 Opus 5.5 怎么分工的教程，没有给出这组并排数字。本期新的是同一套 Claude Code 任务上、针对这两个模型的通过率和单位成本。
实际影响：若你的编码任务和这 52 道题类似，按他的数字，换 Fable 5.2 几乎加不上通过率，还更贵；他认为现在还看不出高下，要把更难的题纳入评测。具体任务列表和算法以仓库里的报告为准。

Guillermo：用 feature flag、推送门禁和指标监控，让 agent 在生产环境交付
5. Guillermo Rauch 写：「以后的代码都会由 agent 这样交付」——agent 写出带 feature flag 的代码，推送时走证明检查和安全审计这类验证门禁，再由 agent 盯指标。他给出眼下就能用的 Vercel CLI 命令：`vercel flags`、`vercel metrics`、`vercel deploy`。他引用的是 Marc Lou 的经验：已经几个月没碰 localhost，先让 AI 把功能只对自己在生产环境可见，确认后再放给用户，并让 agent 按小时/天检查日志和数据库。
背景：昨日简报的 Workflow SDK 5 讲的是耐久工作流运行时；这条讲的是用 feature flag 在生产环境里验收，再逐步放量，不是同一个发布。
实际影响：已经在用 Vercel 的人，可以按这三条 CLI 把「只对自己可见的生产验收」跑起来；他描述的是一种工作流，并不等于所有仓库默认已经接好了证明检查或安全审计门禁。

Aaron Levie：更多工作会变得「像编码」，以适配 agent 所长
7. Aaron Levie（@levie）认为，模型在编码、工具使用、计算机使用和数学这类任务上还会继续变强，因此「会用软件干活、或能从零写代码」的 agent，进步速度会快过其他知识工作。一种可能是只有一小部分工作能被自动化；但他认为更可能发生的是：越来越多工作会变得「像编码」，以适配 agent 擅长的事。他举例：近几个月的模型已经能生成动画视频、游戏和产品的 3D 模型，工具使用也让 agent 用上了人们本来就在用的软件，这在网络安全、生命科学和金融等领域都有帮助。他的判断是：模型不必「什么都懂」，真正关键的是「会用或会写软件」加上足够的领域判断；这一组合一旦成立，知识工作被 agent 加速的速度还会再上去。
背景：11 月 9 日简报里，他谈过每隔 3–6 个月重试旧题、以及从对话节奏变成可并行的 agent 群；本期把原因收束到「工作形态会向编码靠拢」，而不是只重复「要多试几次」。
实际影响：做产品或流程设计的人，可以把「这件事能不能改写成 agent 可调用的软件或可生成的代码」当成一道检查题；这是他的判断，不是某一家产品的发布说明。
