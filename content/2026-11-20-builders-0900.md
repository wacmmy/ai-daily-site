Josh / Gemini：Mac 版应用上线 Computer use，可在独立窗口里操作电脑
2. Guillermo / Vercel：发布实验原语 Board，给人和 agent 共用的「headless Slack」
3. Vercel 官方账号在 11 月 19 日 10 时左右（上海时间）宣布推出 𝚟𝚎𝚛𝚌𝚎𝚕 𝚋𝚘𝚊𝚛𝚍，称作人和 agent 共用的安全留言板：给 agent 一个共享的任务处所，用来搭建 swarm 和软件工厂，并可为人和 agent 分别设置权限。官方标明这是实验功能，欢迎试用和反馈。Guillermo Rauch（@rauchg）随后发帖，称这是他见过最印象深刻的进展之一，也认为对现有技术是一次重要推进。他把留言板比作「给 agent 用的 headless Slack」（或回想 IRC），并写：人和提示只是系统的种子，随后可以有大量 agent 以去中心化方式运行，这对软件工厂、可自我优化的系统和科学研究都有用。他强调 Board 在设计上不绑定特定模型、harness 或托管平台，「只要带上你的 agent，给他们我们的 CLI」。官方博客《Introducing Vercel Board》写：单个 agent 还可以用 Markdown 跟踪工作，但跨多个 agent 和子 agent 时，还缺少专门用来跟踪任务、委派、状态、日志和完成结果的原语。Vercel 先在内部两处试用：安全 agent 集群用它跟踪漏洞分析和修复；见到效果后，又把 v0 的 software factory 迁到 Board 上，并称现在合并的 PR 已超过 50%。博客写它与 harness 无关，Claude Code、Codex、Pi、OpenCode、eve、fx、Mastra 和 LangChain 可以像在同一个 harness 里那样协作。安装 skill 的命令是 `npx skills add vercel/board`；也可用 CLI 领取任务、发更新、完成任务，或用 `npx @vercel/board inspect` 打开查看器。当天稍晚，Guillermo 又补充：Board 没有沉重或充满观点的界面，「是基础设施，不是产品」；因为界面现在可以按场景生成，安全团队可以只看漏洞数量和严重级别，他也见过内部工厂主要是 TUI，或经 Slack agent 管理、人只负责看结果和给反馈。他把 Board 比作 agent 的 Redux 状态层。Vercel 的 Malte Ubl（@cramforce）同一天写了两个内部工厂例子：一个把 Linear 工单同步进 Board、跟踪催促审批以免催得过勤，并用专门 agent 处理 GitHub / Linear 回覆、另设 needs-you 板向工厂负责人提问；另一个做 agent swarm 的自改进，把决策、假设、日志和 traces 写到中央 Board，并让不同 harness（他在 Claude 里交互，沙箱里跑 fx）经 Board 通信。
背景：这和此前报过的 UI SDK、eve 1.0 不是同一层——Board 要解决的是多个 agent 之间如何共享任务和上下文，而不是生成界面或单独部署一个 agent。
实际影响：想试的人可以按官方博客给 agent 装 `vercel/board` skill，或把 https://vercel.com/board-getting-started.md 交给编码 agent 帮忙搭建。它仍是实验功能，接口和能力可能还会改；官方写的 v0 factory「合并 PR 超过 50%」是内部结果，不是对外部用户的承诺。

Amjad / Replit：用 Missions 三天做出开源本机助手 Amuse
4. Amjad Masad（@amasad，Replit）在 11 月 20 日 5:55（上海时间）发帖：「Build your own Muse-like personal agent with one prompt。」他引用的是 Replit 官方在 5:15 发出的帖子。官方写：各家公司已在个人 AI 助手上投入数十亿美元，但这些助手是租来的，记忆、聊天和登录都放在对方的服务器上。他们给 Replit Missions 出了一道题：复制一款领先的 AI 助手；三天后做完，并用 Security Scanner 查找和修补漏洞，确认最终产品可以安全使用。产物叫 Amuse：免费、开源、在你自己的电脑上运行；能做研究、浏览、设提醒和做小应用，行动前会先问你，数据和登录留在本机。GitHub 仓库 README 写得更具体：Amuse 在你自己的电脑上为单人运行，需要一把 OpenAI API key 和 PostgreSQL，不需要再注册别的账号或托管服务；它能做带来源的网页研究、在对话里用可观看也可接管的实时浏览器、设提醒和后台检查、把目标拆成计划并继续推进，也能做带保存数据的小应用。发送、提交、付款前会先问你。仓库地址是 github.com/replit/amuse。
背景：11 月 18 日简报已经报过 Replit 推出 Missions。本期新的是用 Missions 在三天内做出并开源一个可在本机跑的个人助手，不是 Missions 本身再次发布。
实际影响：想自己跑的人，仓库 README 给了 Docker Compose 快速起步：克隆 github.com/replit/amuse，把 `.env.example` 复制为 `.env` 并填入 `OPENAI_API_KEY`，然后 `docker compose up -d --build`，在本机打开 http://localhost:3000。它还需要 PostgreSQL（Compose 会一并启动），服务默认只绑在 `127.0.0.1`，README 写明不要暴露到网络或公网，也没有登录。Agent 默认用 `gpt-6.2-sol`，较快的步骤用 `gpt-6-luna`，网页搜索、生图和语音也走同一把 OpenAI key，并建议在 OpenAI 项目上设置花费上限；另外有 `AMUSE_DAILY_LIMIT`（默认 2000 个用量单位），到顶后当天会停，后台任务次日再恢复。仓库还写：这是给一个人、一台电脑用的小应用，目前没有推到手机；发送、提交表单、付款和新的定时任务前会出审批卡。

Steinberger：OpenClaw 已修 GPT-6.2 的 instructions 缓存问题，多数 harness 尚未更新
6. Peter Steinberger（@steipete）在 11 月 20 日 2:42（上海时间）发帖：他昨天已在 OpenClaw 里合入针对该问题的修复，「适用于少数使用嵌入式 harness、而不是把 Codex 当插件来用的人」；「most harnesses aren’t updated yet」。他引用的是 @bebuu_ai 在 11 月 19 日 13:44（上海时间）的说明：如果你这周发现 GPT-6.2 Astra 或 Sol 的 API 账单突然升高，值得知道还有一个缓存问题。该说明称，OpenAI Codex 的 issue #62312 发现：在 GPT-6.2 Astra 和 Sol 上，放进 Responses API 请求顶层 `instructions` 字段的内容实际上不会被缓存，每轮的 cached tokens 都是 0，尽管 OpenAI 自己的诊断会错误地报告 cache hit。影响被写得很具体：从 GPT-6.1 Sol 迁到 6.2 Sol 后，实际缓存命中率从 97.4% 降到 46.4%，相当于每一步有 6.4 万到 7.2 万的系统 tokens 按全价计费。OpenCode 里已经有一个变通办法：把 system prompt 放到 input 里靠前的 developer message 中。以上缓存命中率和 token 数字来自该帖对自己迁移的描述，不是 OpenAI 官方口径。
背景：GPT-6.2 Sol 与 Astra 已在 11 月 18 日简报中报过上线。本期新的是 API 计费侧的缓存问题，以及 OpenClaw 对嵌入式 harness 的修复。
实际影响：如果自己的工具把系统提示放在 Responses API 的 `instructions` 字段里，不要只看诊断里的 cache hit，最好核对实际 billed / cached tokens。用 OpenCode 的人可以按该帖改放置位置；用 OpenClaw 嵌入式 harness 的人，按 Steinberger 的原话，修复已经合入。把 Codex 当插件用的路径，他写明不在这次修复范围内。其他 harness 是否已更新，需要各自确认。
