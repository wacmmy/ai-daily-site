DeepSeek
发布Harness v0.2.2-rc.1，最低Node.js升至24.9
11月4日21:07，DeepSeek发布Harness v0.2.2-rc.1，作为0.2.2的第一个候选版，汇总自v0.2.1-rc.5以来的变更。相对昨天的alpha.3，这次把最低Node.js提高到24.9，单张图片上限提高到50 MiB，界面增加日语、西班牙语、法语、德语、俄语和巴西葡萄牙语。Web Fetch不再拒绝非公网地址。实验性插件subagent_oar可以把独立任务交给本机的Codex或Claude CLI。自部署的PTC节点要把SSH协议从2升到3，bootstrap和SSH helper必须一起升级。
背景：昨天的v0.2.2-alpha.3已经把文件修改的先读防护默认关闭，并加入变更请求与工作树、默认关闭的apply_patch。这些都包含在本候选版里。
实际影响：Node.js低于24.9的要先升级运行时。自建PTC节点不同步升级会接不上。Web Fetch用于内网或代理时，部署方需要自己限制出网。
来源：https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1

月之暗面 Kimi
Kimi Code 2.5.0发布，运行中可切换模型
11月4日19:52，月之暗面发布Kimi Code 2.5.0。代理正在工作时也可以使用/model和/effort：已经开始调用模型的这一轮保持原设置，下一轮再生效。可以分叉正在运行的会话，也可以从某一历史轮次分叉。多目录项目会合并各目录的技能，同名时主目录优先。创建会话时可以用--environment指定SSH、Docker或自定义命令环境，并用--environment-cwd指定目录。全局全文索引改为默认关闭。服务端去掉subscribe和unsubscribe，客户端改为发送subscribe_v2，断线后要再发一次。
背景：上一稳定版是10月30日的2.4.1。
实际影响：升级后默认不再后台扫描历史会话做全文索引。需要时把配置里的global_search设为true，或设置环境变量KIMI_CODE_GLOBAL_SEARCH=1。接入服务端WebSocket的客户端要改订阅方式。
来源：https://github.com/MoonshotAI/kimi-code/releases/tag/@moonshot-ai/kimi-code@2.5.0

公开理论计算机科学评测TCSExam
11月4日19:44，月之暗面在GitHub公开TCSExam，许可为Apache-2.0。它评测模型加代理在可验证的理论计算机科学任务上的表现。Full有100题，Lite有20题，四类为定理证明、求解器工程、构造和开放猜想。默认代理是Kimi Code，也支持Claude Code、Codex和Grok Build。运行需要Linux x86-64、Python 3.12或更高版本，以及Docker。
实际影响：Full默认在做题过程中给出评判反馈，Lite默认先做公开自测、事后再做隐藏评判。两套结果要分开报告。

腾讯混元
Hy4正式版上线，视觉理解可调用，权重仍未放出
11月4日，腾讯混元发布Hy4正式版。腾讯云调用说明写明，相比Hy4 preview，正式版强化了Agent、长程和真实生产力任务，并首次加入视觉理解。调用名为hy4，上下文1M，最大输入960k，最大输出64k，支持图片理解。目录价与preview相同：输入6元/百万tokens，输出18元，缓存命中0.3元。价格页写明，自该说明发布之日起至2026年12月31日23:59:59（北京时间），调用按目录价的50%结算，之后恢复目录价。科创板日报称参数量为770B，已在TokenHub、WorkBuddy、CodeBuddy、元宝、企业微信智能助理和ima上线，并首次支持电脑操作，权重将于近期开源。
背景：10月29日的大会只做了发布预告，当时没有下载或API。这次新的是正式版已经可以按hy4调用。
实际影响：按量费用在年底前按目录价的一半结算。权重现在还不能下载。

Hyra结果仓库加入单细胞模型HyCell
11月4日0:56，混元把HyCell并入Hyra-results。这是1610万参数的单细胞嵌入模型，把一个人类细胞的原始计数映射成512维向量，在不含细胞类型标签的7950万个细胞上预训练，权重和Python包hycell都在该目录里。
实际影响：新细胞的嵌入可以用来做聚类、批次整合和注释迁移，解码器可以把嵌入还原成基因表达。

Hyra结果仓库加入量子码距工具hyqec
11月4日14:47，同一仓库加入hyqec，用来计算量子稳定子码的距离，并为每个答案附上可以复核的证据。说明写明，qldpc-challenge板上184个一般（非CSS）稳定子码里，165个已经算出可证明的精确距离，且与板上给出的距离一致。目录里有证明程序hyqec-verify 0.3.0，以及按书面规范独立实现的检查器hyqec-check 2.0.2。
实际影响：非CSS码的精确泡利权重距离可以在本目录复算，检查器不导入证明程序的代码。
来源：https://github.com/Tencent-Hunyuan/Hyra-results/tree/main/AI4Science/hyqec

MemHub构建41上线，lite检索能找回已整理过的原文
更新日志把MemHub 1.0.6改记为11月4日、构建41，基于hy-memory 2.0.14，提供Linux x64/arm64与macOS arm64。hy-memory 2.0.14于当天17:52上传到PyPI。相对11月2日的构建37，新安装要在引导里选择lite或pro，pro要等生成模型可用才算完成，已有安装仍保持pro。lite检索改为在原始对话上按向量分数返回active和shadow，因此从pro切到lite后，已经被整理过的历史仍能搜到；pro和ultra的原始检索仍只看active。2.0.14的search可以显式传入statuses，默认仍只返回active；把statuses传给非原始检索或scene为all会报错。简体中文界面现在对所有对话使用中文提示和中文记忆，包括英文对话。长同步历史不再把写入卡住几十秒，每个来源只保留最新20条已完成的导入任务。
背景：11月2日的1.0.6已有lite、pro、ultra三档，当时的构建号是37，钉的是hy-memory 2.0.11。
实际影响：从pro换到lite之后，先前整理过的原始对话还能搜到。不传statuses的SDK调用行为不变。
来源：https://github.com/Tencent-Hunyuan/Hy-Memory/blob/main/CHANGELOG.md
来源：https://pypi.org/project/hy-memory/2.0.14/

MiniMax
Python SDK 0.1.0稳定版发布，安装不必再加--pre
11月4日10:11，minimax-code-sdk 0.1.0上传到PyPI。这是首个稳定版，公开接口与昨天的0.1.0b1相同。提前结束流式循环现在会停掉命令行并释放线程。取消改为先发SIGTERM，并给命令行60秒退出时间。线程在创建时固定工作目录，之后改变进程目录不会把下一轮带到别的工作区。Windows上不再经由cmd.exe启动安装器里的mcode.cmd。
背景：昨天的版本是公测0.1.0b1，安装要加--pre。
实际影响：现在用pip install minimax-code-sdk即可。在循环里提前退出会真正停掉本轮命令行。
来源：https://pypi.org/project/minimax-code-sdk/0.1.0/
仓库：https://github.com/MiniMax-AI/minimax-code/blob/main/packages/code-sdk-python/CHANGELOG.md
