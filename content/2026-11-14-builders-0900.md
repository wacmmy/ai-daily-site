Guillermo / Vercel：Workflow SDK 5 面向 agent 循环加速，默认加密载荷
1. Vercel 官方账号宣布 Workflow SDK 5 已推出，定位「为快速的 agent 循环而建」：延迟和开销最多可降约 25 倍，每条载荷默认加密，并支持按区域隔离工作负载和故障转移。Guillermo Rauch（@rauchg）写道，这对 agent 是很大一步：到第一步的时间、步骤之间的时间都明显改善；他们加码了加密和安全；整体系统的可靠性已在大规模下得到验证，还梳理了许多细节和容灾场景；底层的耐久日志也可以复用给任意 agent harness，并因此有了 durable-harness。官方博客补充了可核对的数字（在 iad1、托管的 Vercel World 上，对比 v4.8.12 与 v5.2.0）：到第一步的 p75 从 418 毫秒降到 172 毫秒；步骤之间的 p75 从 618 毫秒降到 109 毫秒；长任务后期开销的 p75 从 1,748 毫秒降到 70 毫秒（约 25 倍）；1,020 步任务的中位完成时间从 21.0 分钟降到 3.0 分钟；一段 52.4 秒的录制流式回复，中位送达从 226.1 秒降到 53.5 秒。安全方面，步骤入参和返回值等会在离开你的代码前用 AES-256-GCM 加密，每次运行有独立密钥；在 Vercel 上无需额外配置，后端只存密文。v4 里所有运行的状态都在华盛顿（iad1），v5 把工作流基础设施铺到了每个 Vercel Function 区域，运行默认待在启动它的那个区域。Worlds 是共用的耐久层；durable-harness 可给已有 harness 加上耐久性，官方写明目前支持 Pi 和 OpenCode，Claude Code 与 Codex 在 Vercel Sandbox 里是实验性接入。此外还有运行中取消（AbortController）、可搜索的 run attributes，以及仍在 beta 的 Python SDK。安装可用 `pnpm add workflow@latest`。
背景：昨日简报刚报过给 agent 生成界面用的 UI SDK，那是交互原语；本期是耐久工作流运行时的一次大版本，不是同一层东西。
实际影响：已经在用 Workflow SDK 的人可以按官方升级文档升到 v5；想给现有 harness 补上崩溃后续跑的能力，可看 durable-harness，但 Claude Code / Codex 目前仍是实验性接入。文中基准是特定环境和版本上的测量，不能直接当成自己应用的保证。

Guillermo / Vercel：Sandbox 在部分区域启动最多快约 4 倍
2. Vercel 开发者账号发 changelog：Vercel Sandbox 现在在华盛顿（iad1）以外的区域，若复用的镜像数据能从区域缓存读取，初始化最多可快约 4 倍。启动时会就近读缓存里的镜像，命中后不必再回到 iad1 的源站存储；托管镜像和基于 Vercel Container Registry 的自定义镜像（包括由这些镜像做的快照）都支持。内部端到端基准（Vercel Managed Images）写：巴黎的启动时间大约下降 75%，首尔从约 3.5 秒降到 1.05 秒；离源站更近的区域，提升通常会小一些。Guillermo 引用这条更新，并回复说 Vercel 已经跑了 10 年沙箱，每次构建都会拉起一个，目前在 19 个区域运营。
背景：这是 Vercel 自己的 Sandbox 启动路径优化，和 11 月 6 日简报里 Replit 公开的微 VM 沙箱引擎不是同一件事。
实际影响：主要在 iad1 以外区域反复拉起 Sandbox、且镜像能命中区域缓存的工作负载会更快；本来就靠近源站的区域，不必期待同样的倍数。

Steinberger：OpenAI 团队公开内部如何给持久 agent 设安全边界
3. Peter Steinberger（@steipete）发帖：「我的团队写了我们如何在 OpenAI 内部运行持久 agent。」他引用的是 Kevin S Lin 的帖子和开发者博客《Securing persistent agents like OpenClaw at OpenAI》。文章把持久 agent 和普通 Codex 会话区分开来：后者有固定目标和人在旁边盯，前者是 7×24 跑、范围更宽，还可以在没有人下达指令时主动行动。OpenAI 目前在全公司部署了持久 agent，其中有数百个 OpenClaw agent；文末又写现在有 500 多个 agent 在后台主动干活，例如根据产品反馈自动开 PR、持续做新功能的数据实验。他们采用的做法包括：把可信的确定性逻辑（网关，负责组网、身份和沙箱配置）和不可信的模型执行（agent harness）拆到不同容器乃至不同集群；用沙箱限制网络（组织管理的域名白名单，并显式封掉受限地址）、工作区写入范围、进程隔离（codex linux sandbox），密钥走凭证代理，不把密钥直接暴露给 agent；关掉 danger-full-access，网页搜索只用经过 OpenAI 自有索引的 cached 模式；用 Auto-review 让第二个 agent 监控并批准主 agent 的动作，把人的注意力留给高价值审批，这一项在他们的 OpenClaw 部署里对所有动作强制开启，OpenClaw 和 Codex 都原生支持；每个 agent 有独立身份，并关联到 ChatGPT Service Account，以便审计和在需要时关掉推理。文章最后提到，Dev Day 上宣布过开源、厂商中立的控制平面 OpenClaw Enterprise（OCE），若使用标准 Codex preset，文中许多防护是内置的；项目仍在试点，计划年底到 1.0。
背景：名单里的 dots / OpenClaw 这类持久 agent，和一次任务型的编码会话不是同一类部署问题；这篇文章讲的是 OpenAI 自己在公司里怎么管它们，不是发布新产品。
实际影响：要在企业环境跑 OpenClaw 或类似持久 agent 的人，可以直接对照网关与沙箱拆分、域名白名单、凭证代理和 Auto-review 这些做法；如果准备用 OCE，需注意它仍在试点。

Garry Tan：公开 Idea Miner skill，把近两天记录排成「下一步该做什么」
4. Garry Tan（@garrytan）发帖：如果你的个人 agent 能在你使用的过程中递归地自我改进，现在可以做到；他做了 idea-minder 这个 skill。对应页面的正式名称是 Idea Miner：每天早上，AI 阅读近两天实际发生的事（会议、笔记、记忆里新出现或改过的页面），给你一份很短的、排好序的「值得做的事」清单，并指出最该先做的那一件。它会用 gbrain.io 为你保存的记忆（页面写明已包含、不用另接），也可选连接 Google 或 Microsoft 日历，以及 Granola、Circleback 这类会议记录工具。Skill 本身免费：可以复制、下载后在自己的 AI 里跑，也可以让 gbrain.io 在云端帮你装好并定时运行。页面公开了完整 skill 文本，名称是 idea-miner：汇总过去 24 到 48 小时的会议记录、记忆页面和已有 skill 列表，寻找重复出现的工作，产出 3 到 6 个具体可做的事项（新 skill、agent、工作流或一段代码），必须能指回真实发生过的事，禁止编造；已有的就不要再推，或改成对现有 skill 的具体升级；每次运行存成带日期的记忆页，方便对照哪些想法往前走了、哪些安静了。页面建议作为每天早上 7 点的定时任务，但设定前要先问你一声。示例对话被明确标明是虚构的，用来说明输出长什么样。
背景：这是一条可复制的 skill，不是新模型或新应用商店上架；和此前他公开的 GHarnessEvals、GBrain 工作区是同一类「自己用、也公开出来」的东西。
实际影响：想自己跑的人可以直接在该页复制或下载完整 skill；不想自己托管的，可以用 gbrain.io 代跑，但日历和会议记录需要自己去连接。

Peter Yang：Fable 5.2 与 Opus 5.5 怎么分工，附视频和文字教程
5. Peter Yang（@petergyang）发帖：因为 Fable 5.2 和 Opus 5.5，Claude 又成了他的日常主力。他分享了一份教程，讲自己在 5 个真实场景里分别用哪个模型：给收件箱当参谋、职业和生活建议、自动做播客后期、做一款手机健身应用、以及陪伴母亲治病。他还提到会分享一条让 Fable 改进你现有 skill 和工作流的 claude-api 提示词。免费可看的视频在 YouTube；同题文字版在他的 newsletter。公开导语里的建议是：把 Opus 当日常主力，把 Fable 留给最难的活。他写，自己用 Opus 处理邮件、自动化工作流和做个人应用，用 Fable 做业务上的战略性建议、照顾母亲，以及检查自己的 AI skill 有没有问题。他同时转述了 Anthropic 研究员 Alex 的几条用法：先让 Fable 挑你这个想法的毛病，再动手；用 medium effort（他说 Anthropic 内部也这样）；事先讲清楚哪些要你批准、哪些可以自己做；把整个项目交给它，而不是一次只丢下一步。文字版标明由 Anthropic 赞助，但观点是他自己的；付费墙后还有按场景可复制的提示词。
背景：11 月 10 日简报里，Dan Shipper 和 Peter 都做过 Fable 5.2 的上手实测；那几篇还没有他把「日常用 Opus、难点用 Fable」落到具体工作流上的完整教程。
实际影响：想看他怎么分工，可以直接看免费视频；若要复制各场景的完整提示词，需要看付费的文字版。
