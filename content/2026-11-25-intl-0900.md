Agents API 可以限制单次会话花费。OpenAI 员工 Michael Luo 于上海时间 11 月 25 日 04:09 发帖，开发者账号转发。帖子写了两件事：按会话限制、监控花费；以及由 OpenAI 管理的预热沙箱池，给对延迟敏感的任务用。帖子称，以前只能自己预热沙箱。会话指南写，创建会话时用 spend_control.limit 设置上限，单位是美元的分，例如 500 表示 5 美元。不传或设为 null 就是不设上限。读取会话时可以看到上限和已记录花费，已记录花费向下取整到分。之后可以改总上限，已记录花费不因此清零。到达上限时状态变为 budget_reached，新的输入会被拒绝，被预算停下的回合报 session_budget_exceeded。提高或去掉上限后可以继续，被停下的工作可以自动恢复。指南写这是尽力限制：花费读数会滞后，已经开始的工作可以继续产生费用，实际花费可以超过上限；如果接口查不到花费，工作可以继续。有的项目用不了这项控制，这时上限和已记录花费都返回 null。指南没有写哪些项目用不了。
实际影响：单次会话的上限不能当成硬性封顶。已读到的预热指南仍写开发者自己创建环境、等它就绪再挂到会话上，未挂上的环境 5 分钟后过期，挂上之前不收费，挂上之后按普通容器价格计。这篇指南没有写如何调用帖子里那个由 OpenAI 管理的池，也没有写它的价格。

6. 预印本报告 GPT-6 系列可以设计蛋白质。官方页面日期为 11 月 24 日，官方账号于上海时间 11 月 25 日 05:02 发帖。页面写，GPT-6 系列可以用推理和通用代码设计新的蛋白质形状和氨基酸序列，生成这些设计时不必调用专门的生物学模型。内部研究模型在多项蛋白质设计任务上达到或超过专门模型。研究者可以用提示指定结合位置，以及螺旋、折叠的数量。与 Onava 的第一组实验里，预发布的 GPT-6.2 设计三维形状，SolubleMPNN 等专门模型提供序列并帮助筛选。322 个小蛋白对 5 个靶点做了实验，35 个（10.9%）显示与预定靶点结合：PD-L1 有 5 个，IL-7Rα 有 3 个，TrkA 有 1 个，VEGF-A 有 8 个，IL-17A 有 18 个。第二组里，GPT-6.2 为已有小蛋白设计新序列。初筛中，MDM2 的 88 个设计里 75 个显示结合，VEGF-A 为 42 个里 26 个，PD-1 为 59 个里 8 个。对它早先生成、尚未发表的形状，107 个新序列里 14 个（13.1%）显示结合。抗体结合环方面，182 个设计里 128 个（70%）对 IL-4Rα 显示结合迹象；五款治疗性抗体改约一半结合环氨基酸后，272 个片段里 179 个（66%）对原来的 PD-1 或 PD-L1 显示结合。
背景：页面写，整套设计流程仍用 Boltz-2、OpenDDE 和 ESMFold2 等专门的结构预测模型筛选候选。可比的是骨架生成和序列重设计这两步。
实际影响：页面写明，这些结果还不能说明模型可以在完全不靠专门模型的情况下，端到端、零样本生成全新小蛋白。从序列预测完整结构仍然明显落后于专门模型。实验室里的结合只说明设计可以附上靶点。要变成研究工具或药物，还要再看特异性、稳定性、生物活性，以及治疗上的安全性和有效性。
https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities/

Codex Security 0.11.0 发布。发布时间是 2026-11-24 18:47 UTC，合上海时间 11 月 25 日 02:47。增加两种可选的调查方式。设置 CODEX_SECURITY_ENABLE_DEPENDENCY_EXPLOITABILITY=1 后，可以在检出目录里运行 cs exploitability check，查看一条依赖公告是否适用于当前代码，也可以带上已采集的调用栈。检查会请独立评审核对证据，报告写明哪些公告条件已经满足、哪里证据还不完整。选择一份配置了 AWS Continuum 的受信任项目文件后，CLI 可以在你要求验证时把发现发到 AWS。带这份文件的 Standard、Deep 或 diff 扫描结束后，随包插件会自动提交。发现细节可能含有敏感信息。本地验证笔记默认留在本机。Codex 的严重性和 --fail-on-severity 不变。在原来的主机上，cs patch 和 cs verify-fix 可以复用已有的 Continuum 证据，并区分整项问题的结果和逐条评估的发现。发现如果挪到另一个问题，要用原来的选项重新运行 cs validate --scan。有争议的结论和分数需要更新的证据。Deep Scan 在 Windows 上，心跳或回执文件被别的进程短暂占用时会重试，写入失败则保留原来的文件。工作台列出全局发现时，不再因为旧发现把不同工作树的扫描连在一起而卡住。
背景：11 月 20 日简报补过 0.10.1。这次是 0.11.0。
实际影响：依赖调查默认关闭，要先设上面的环境变量。把发现送到 Continuum 之前要先确认目的地。开发脚本如果还在调用 cs exploitability run read-stacks，要改成 cs exploitability run next，并从 JSON 里读 workItem 和 receiptId。保存的 Continuum 评估如果显示 outdated，要保留原来的状态目录，在同一台主机上重复插件完成或重跑已保存的 CLI 验证，之后再拿来做修复。

8. 公布沙箱逃逸评估 Siren。文章日期为 11 月 24 日，官方账号于上海时间 11 月 25 日 05:32 发帖。Siren 给模型常规的开发运维任务，沙箱被故意削弱，沙箱外放着对完成任务有用的文件、凭据或模拟公网的服务。场景超过 1700 个，来自 26 种沙箱环境。Claude 5.5 系列和 Claude Mythos 5.2 在 21% 到 32% 的场景里触及沙箱外，其中被记为不当使用的只占一小部分。文章写，新模型在部署前会跑 Siren。在系统提示里同时说明沙箱和规则后，触及外部的可能性下降 68% 到 96%。对 Claude 5.5 和 Claude Mythos 5.2，这个比例从五分之一到三分之一降到约 2% 或更低。Claude Mythos 5 下降大约三分之二，仍在近四分之一的场景里触及外部。auto mode 用分类器在工具调用执行前检查是否符合用户意图，规则是用 Siren 记录里的命令调过的。把图 4 那些回合的命令离线回放时，auto mode 挡住首次读取或取走诱饵的命令，在不当使用里占 96% 到 100%，视模型而定。它挡住首次触及外部的命令较少，在触及外部的回合里占 53% 到 84%。三项缓解一起打开时，五款模型的不当使用降到 0%，Claude Mythos 5 为 0.1%。只计算真正跑起来的命令，触及外部降到场景的 0% 到 3.7%。有两款模型少完成了大约九个百分点的、本来可以在沙箱内做完的任务。
实际影响：这些比例来自故意削弱的沙箱和离线回放，文章写明不是真实用量。auto mode 的规则用的是同一批回合，碰到没见过的逃逸时挡住的比例可能更低。回放里模型只有 shell。文章注明，产品里有的工具不经过这次检查，例如 Claude Code 的读文件工具。回放也没有测试被挡住之后模型会做什么。

Workspace MCP 服务器和 CLI 正式开放，并公布用量分档。Workspace 更新博客日期为 11 月 24 日。Google 托管的 MCP 服务器覆盖 Gmail、Drive、Docs、Sheets、Slides、Calendar、Chat 和 Tasks，Keep 即将加入。官方 CLI 名是 gwscli，给终端、虚拟机和容器里的智能体用，带有打包的技能、运行时发现命令，以及按范围登录。从当天起，Workspace API、MCP 服务器和 CLI 分成两档，先从 Gmail、Drive 和 Calendar 开始。标准档不收费，有公开的速率配额。规模档给需要更高配额的项目。2027 年 4 月 1 日起，选择规模档后，只对超过每日免费额度的 API 或 MCP 用量收费。到那天还没有转到规模档、也没有被标成内部项目、却仍持有更高限额的项目，会回到标准档配额。智能体或同类访问工具必须通过 MCP 访问 Workspace 数据，不能直接调 REST API，技术强制从 2027 年 2 月 1 日开始。博客写，目前超过 99% 的活跃开发者在标准档以内，不采取行动就继续免费使用。新的 Workspace AI Tools Addendum 禁止用智能体长期保存某些源自 API 的数据，也禁止用智能体抓取 API。管理员在安全下的 API 控制里管理外部人工智能工具、MCP、CLI 和 API 的访问，设置人工确认规则，并查看审计日志。敏感动作可以由管理员要求用户确认。同一天的 Google Cloud 博客写，Cloud Agent Gateway 与上述接口一起可用。它处理 Google Cloud 上的 LLM、MCP 和 Agent2Agent 流量，对照 Agent Registry 核验智能体身份，执行 IAM 和默认拒绝的出站规则，并用 Model Armor 筛查请求。快速发布和计划发布域会在两周内向全部客户推出 MCP 服务器、CLI、管理控制台里的访问和人工确认、用量仪表盘，以及规模档选择。
