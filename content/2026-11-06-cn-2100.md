DeepSeek
Harness公布日活154万，准备做官方插件市场
11月5日晚，DeepSeek Harness官方公布产品和社区进展。截至11月4日，以使用官方API的用户为统计范围，日活跃用户154万，日消耗约92万亿token。发布至今第三方插件约3.5万个，约60%的活跃用户制作或安装过至少一款。官方写明，将提高插件API的稳定性和兼容性，完善插件安全机制，并建设官方插件市场。面向插件作者的支持计划还在筹备，方式包括Token激励、技术交流和作品推荐，具体办法要等社区反馈后再定。
背景：v0.1于8月13日上线，桌面端于9月29日发布。这次新的是使用数据和插件市场计划。
实际影响：插件市场和支持计划都还没上线，作者现在还不能按新计划领取Token。
来源：https://www.ithome.com/1/023/011.htm

月之暗面 Kimi
Kimi Code 2.5.2发布，工具定义变化不再报重复声明
11月6日15:48，月之暗面发布Kimi Code 2.5.2。MCP工具定义发生变化时，select_tools不再报重复工具声明。网页端在会话还在跑时，插入的消息不会再被错误地排进队列。通过HTTP打开网页界面时，也可以创建项目。

实际影响：升级到2.5.2后，工具列表中途变化不应再把这一轮打成重复声明错误。用HTTP打开网页版时，可以新建项目。

字节豆包
公开Cola2推理代码和权重，训练代码未放出
11月6日，字节Seed公开Cola2。这是连续潜空间语言模型，把文本按语义跨度压成连续向量，用大约40亿参数的DiT生成这些向量，再解回离散token。放出的检查点用3460.3亿个源token训练，论文报告的八项任务平均分为60.10。GitHub只有推理实现、命令行和可续跑的八任务评测，没有训练代码。权重、分词器和评测数据在Hugging Face，共八个分片。代码许可为Apache-2.0。权重、分词器和评测数据各自沿用原条款，模型卡没有另写许可名称。
背景：论文于10月22日上架arXiv。这次新的是推理代码和可下载的检查点。
实际影响：复现推理可以用仓库里的Transformers实现。训练脚本没有放出。潜变量采样带随机性，本地分数可以和论文里的60.10不同。
来源：https://github.com/ByteDance-Seed/Cola2
来源：https://huggingface.co/ByteDance-Seed/Cola2

公开Qwen3-30B-A3B三层MoE输出的稀疏自编码器
11月5日晚，字节Seed公开论文所用的代码和权重。TopK稀疏自编码器加在Qwen3-30B-A3B第4、30、46层的MoE块输出上，每层2的20次方个隐特征，每次保留100个，许可Apache-2.0。每一层的sae.safetensors约17.2GB，是四个float32张量。论文于11月5日22:35上架arXiv。编码直接使用MoE块的原始输出，不做归一化。
实际影响：复现贡献统计需要Qwen3-30B-A3B的bf16权重，约61GB，以及transformers 5之前的版本。三层一起跟踪时，说明写明要两张80GB GPU。
来源：https://github.com/ByteDance-Seed/SAE-interprets-MoE
来源：https://huggingface.co/ByteDance-Seed/Qwen3-30B-A3B-MoE-SAE
来源：https://arxiv.org/abs/2611.08089

腾讯混元
开源FlashTopK，给稀疏注意力做精确top-k
11月6日，腾讯混元开源FlashTopK，许可Apache-2.0。这是学习式稀疏注意力在训练和推理里用的精确top-k选择核。仓库写明，完整预填充上，相对稠密打分再加FlashInfer top-k，训练过的索引器快1.7到3.3倍，未训练的快1.2到2.0倍。支持的索引器为32头、每头128维，点名GLM-5.1、GLM-5.2、GLM-5.3、GLM-5.3-Flash和Hy4-preview。GPU为Hopper，包括H800、H20、H100、H200，topk最高4096。安装需要Python 3.10以上、PyTorch 2.6以上、Triton 3.3以上和CuTe DSL 4.5以上。
背景：配套论文HyScale于10月23日上架arXiv。这次新的是选择核代码。
实际影响：同一输入每次得到相同下标，分数并列时保留更小的key下标。进程里第一次调用会编译核，仓库写明大约15秒。
来源：https://github.com/Tencent-Hunyuan/FlashTopK

WorkBuddy里的Hy4推理集群扩容十倍（补报）
11月5日，腾讯混元和WorkBuddy发文称，Hy4从11月4日接入WorkBuddy后，首日就有大量用户在任务队列里把额度用满。团队已把Hy4推理集群紧急扩容到十倍，并提高免费体验额度，之后仍会按用量调配。高峰仍可能限额。过渡办法是改用Hy3，WorkBuddy上Hy3的限免延到11月15日23:59，或者把不急的任务放到晚上。上一期21:30未收录，这次补报。
实际影响：还在撞Hy4额度的人可以先切到Hy3，限免延续到11月15日23:59。Hy4在高峰时段仍可能被限额。

MemHub构建45：超长原文不再把整次检索清掉
11月6日，Hy-Memory把MemHub构建号升到45，产品版本仍是1.0.6，钉的还是hy-memory 2.0.14。原始检索遇到超过2万字符的一轮对话时，不再让整路原始结果失败、网页上显示成没有匹配；超限文本会截断后返回。选择全部应用时，原始对话改为读取所有仍连接且未撤销的来源。Lite的三维地图改为最多20段原始对话、最多300个节点，刷新失败时保留上一次成功的图。

实际影响：一条特别长的原文不会再把已经命中的更短结果一起藏掉。Lite地图不会再把全部历史节点一次画出来。
