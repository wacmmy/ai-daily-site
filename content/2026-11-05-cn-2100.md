百度文心
开源文心5.5 Flash Base，预训练终点权重可下载
11月5日，百度在文心发布页放出ERNIE-5.5-Flash-Base。这是稀疏混合专家基座，总参数2800亿，每个token激活140亿，用33.5万亿token从零预训练。训练上下文最高128K，微调和推理支持100万token。放出的检查点停在预训练结束，没有做中训练和后训练。FP8和BF16权重在Hugging Face，许可为ERNIE 5.5 Flash Base Model License Agreement v1.0。官方写明，经过后训练的文心5.5 Flash会随后推出。
背景：这次给的是预训练终点，不是已经能直接对话的成品模型。
实际影响：做领域适配、指令微调或强化学习的团队可以从这个检查点接着训练。分词时要保留BOS，add_special_tokens保持为True。SGLang和vLLM通过completions接口提供服务。
来源：https://ernie.baidu.com/release/ernie-5-5-flash-base/
来源：https://huggingface.co/baidu/ERNIE-5.5-Flash-Base
中文报道：https://www.ithome.com/1/022/785.htm

月之暗面 Kimi
托管智能体正式发布，Harness改由云端提供
11月5日，Kimi资讯页发布Kimi Hosted Agents（托管智能体），把支撑智能体运行的Harness作为云端服务提供给企业和开发者。企业不必自己维护代码执行环境、会话、工具调用和中断恢复，即可获得7×24小时的托管环境，用于长程任务和多智能体协作。平台提供140多个Skills和30多个插件，也可以接入自有工具。首批8个金融模板，覆盖投研建模、深度研究、晨报、IPO跟踪和持仓监控。开放平台写明，费用由云沙箱、模型推理和插件三部分组成，沙箱为每小时0.072元，模型按所选模型的token价另计，插件按调用次数另计。
背景：开放平台更新日志把同一产品的Beta写在2026年9月，当时写明只面向国内企业认证用户。这次资讯页改为正式发布，并写明注册登录platform.kimi.com即可体验。
实际影响：沙箱按每小时0.072元计，模型token和插件调用另计。配套的Kimi Inference Hook仍只对企业认证用户定向开放，检查规则由企业定义，未通过检查的内容不会进入模型推理。
来源：https://www.kimi.com/news/kimi-hosted-agents
来源：https://platform.kimi.com/docs/pricing/hosted-agents

Kimi Code 2.5.1发布，空系统消息不再把会话打成连续400
11月5日17:53，月之暗面发布Kimi Code 2.5.1。动态工具schema带出空的system消息时，会话会反复返回HTTP 400，这个版本修掉了该错误。网页端新会话在第一轮之后会自动生成标题；路径里带空格的本地图片可以显示；实时和重新加载的工具结果会补上图片和视频预览。已删除工作区的会话不再出现在会话列表里。
背景：昨天的2.5.0可以在运行中切换模型和思考强度，也可以从历史轮次分叉会话。
实际影响：升级到2.5.1后，因空system消息连续400的会话不应再被同一错误打断。
来源：https://github.com/MoonshotAI/kimi-code/releases/tag/@moonshot-ai/kimi-code@2.5.1

字节豆包
Seed公开Qwen3-8B-Base的跨层转码器权重
11月5日，字节Seed在Hugging Face公开Cross-Layer-TopK-CLT，许可Apache-2.0。这是给Qwen3-8B-Base用的跨层转码器，36层、每层32768个隐特征，共942亿参数，fp32，模型卡写明合计377GB。每一层的隐特征读取该层MLP之前的残差，并写回该层及之后每一层的MLP输出。编码时在全部层里保留得分最高的360个隐特征。
实际影响：只做编码、不解码时可以不下载解码权重，模型卡写明一张80GB GPU就够。要解码则按说明用8卡跑示例。权重按原始激活使用，不要再乘factors.safetensors里的归一化系数。
来源：https://huggingface.co/ByteDance-Seed/Cross-Layer-TopK-CLT

腾讯混元
公开EmoReward，用上一轮训练轨迹校准情感视频奖励
论文EmoReward于11月4日21:43上架arXiv，官方仓库在同日23:25写入实现。它面向情感视频生成的强化学习：先从提示里规划要看的表情和身体线索，再用多路信号给生成视频打分，并按相位、人脸置信度、冲突和细微程度做门控。RewardMemory根据已经跑完的那一轮训练里各信号的可靠性，给出下一轮使用的有界乘子，不更新奖励模型。论文的实验写在HunyuanVideo 1.5上，并在SD 3.5和FLUX上做了迁移测试。
实际影响：仓库根目录的许可是腾讯混元社区协议，正文写明不适用于欧盟、英国和韩国。
来源：https://arxiv.org/abs/2611.06518
来源：https://github.com/Tencent-Hunyuan/EmoReward

MemHub构建43：采集钩子不再自己写数据库
11月5日，Hy-Memory仓库把MemHub构建号升到43。同一天写入更新日志、尚未归入版本小节的说明写明：one-memory capture不再在钩子进程里打开主数据库，也不再重建已退役的evidence表或直接写队列，而是只读取运行时回执和令牌，把这一轮的JSON发给正在运行的Core，预算1.5秒。Core未运行时，这一轮被静默丢掉，不再退回本地写入。已经由实时文件同步读取的来源，除Qwen Work外且文件同步开着，不再经钩子重复送入。
背景：昨天的构建41仍基于hy-memory 2.0.14，主要改动是lite检索能找回已经整理过的原文。构建43没有更换这个SDK版本。
实际影响：Core没开着的时候，钩子采到的对话不会落库。除Qwen Work外，开着文件同步的来源只走文件路径，钩子不再写第二遍。
来源：https://github.com/Tencent-Hunyuan/Hy-Memory/blob/main/CHANGELOG.md
