Cat Wu（Anthropic / Claude Code）

背景：Cat 是 Claude Code 核心建设者之一，名单上的 Cat Wu。
实际影响：Claude Code 核心人物离任；社区（含 Peter Yang、Thariq）密集致谢「generational run」。
社区讨论：有人问是否为 IPO 锁定期提前走，她回复「no idea and wasn’t a factor for me」。

Boris Cherny（Claude Code）
2. Boris 称：一个个给公司插件登录很烦，所以现在 Claude 可自动连接。Team / Enterprise 管理员预置后，同事第一次用这些插件就会自动连上。官方同步：支持把 Claude 当作 trusted issuer 的 MCP 插件，登录后自动连、免反复授权。
背景：面向企业侧插件与 MCP 接入摩擦。
实际影响：管理员一次配置，团队成员首次用插件即可自动连通。

Guillermo Rauch（Vercel）
3. Vercel Security Review 公测：内部安全 agent（昵称 @hacker）会对每一行代码自动审计；现已对外开放，不部署在 Vercel 上的仓库也能开。每次 push 扫变更（缺授权、泄密等逻辑洞），结果进 Security 面板、PR 评论与 CLI，可用 Vercel Agent 一键修，或把 finding 交给自己的 coding agent。Guillermo 称「download a security team as software」。另：`npm i -g ai-cli` 让任意 agent 经 AI Gateway 调视频/语音/图像/文本与 decide；Vercel CI 现可对无 Vercel 项目的 GitHub 仓库启用。
背景：博客写明 11 月 2 日上线公测；Guillermo 11 月 3 日力推内测同款能力外放。
实际影响：Pro/Enterprise 可对所有或选定项目默认开扫；11 月 10 日前安全审查免费，Agent 修漏洞按 Agent 费率计。

Amjad Masad（Replit）
4. Amjad 发安全建议《Make managed cloud environments the default for AI agents》：员工端点上的 agent 正成企业与政府系统性风险；部分机构（如据报高盛）选择禁用 Claude Code 等工具。他主张 agent 应在组织可控、任务级隔离的托管云环境运行，凭证与权限在 agent 够不到的地方强制执行；并引用供应链攻击、个人 agent 连敏感系统、MCP 提示注入等案例。随后又称企业正处 agent 与 vibe coding 采纳的「混乱期」，认真投基建的会甩开只会限制工具的对手。
背景：高盛等禁用端点 AI 工具的新闻刚发酵。
实际影响：把「默认托管隔离云端 agent」写成可执行建议，与单纯禁工具形成对照。
社区讨论：Scott Belsky 称偏好会从 DIY vibe coding 摆回安全 SaaS；Amjad 认同廉价放任 vibe coding，但反对用限制代替基建。

Aaron Levie
5. Levie 称：AI 普及面最广的时候，产出差距反而可能史上最大。几年前就算编码这种最对齐的领域，用得好也大约只多 30–50%，还要花大量时间收拾模型错误、上下文短、交互高度同步；现在长任务、agent harness、更好数据、多 agent 并行，把上限推到约 5–10 倍。站在前沿与完全不跟，产出可差一个数量级，且 RSI 下差距还会再拉大。
背景：此前他谈过「管一队 agent」的岗位描述变化。
实际影响：把「会不会用」从边际效率差，升级成数量级产出差。

Nikunj Kothari
6. Nikunj 称 Claude Code 里仍偏少人用、但自己最爱的两个默认 skill：`/insights` 与 `/playground`。`/insights` 他配了每两周跑一次的 cron，汇总升级用法，再叠 X 书签里的「软件工厂」新做法，形成用法自改进闭环。`/playground` 用来可视化工作流（陌生仓库架构、侧项目学习环），最近爱让 Codex + Claude Code 一起找死代码、热路径与延迟优化。
背景：面向已经用 Claude Code、想挖默认 skill 的人。
实际影响：可直接复用「两周 cron + 书签」和「双 agent 跑 playground」做法。
