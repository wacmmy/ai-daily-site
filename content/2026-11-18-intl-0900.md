OpenAI
1. 发布 GPT-6.2 Astra 和 GPT-6.2 Sol。官方页面日期为 11 月 17 日，官方账号于上海时间 11 月 18 日 01:54 发帖。Astra 面向最难的项目，Sol 面向日常工作。两款都用更少的输出 token 完成要求更高的任务。即日起，Plus、Pro、Enterprise 和 Edu 可以在 ChatGPT Work 和 Codex 里使用。帮助中心写明，这次推出不把两款模型加进普通 Chat。API 模型名为 gpt-6.2-astra 和 gpt-6.2-sol，Responses API 和 Chat Completions 都可用，工具调用必须走 Responses API。Astra 标准价格为每百万 token 输入 8 美元、缓存输入 0.40 美元、输出 40 美元，输入和输出比 GPT-6 Astra 低 20%，缓存输入低 60%。Sol 沿用 GPT-6.1 Sol 的价格：输入 2 美元、缓存输入 0.10 美元、输出 10 美元。Pro 500 可以对两款使用 Ultrafast。Pro 200 首次获得 Ultrafast，先从 GPT-6.2 Sol 开始。符合条件的 Enterprise 和 Edu 要等工作区管理员打开，才有同样的 Ultrafast。API 上两款在发布时都可以用 Ultrafast。网络安全按预备框架达到 Critical，与 GPT-6 Astra 相同；生物与化学达到 High。GPT-6.2 Astra 是第一款对外发布、并在人工智能自我改进上达到 High 的模型。公司称，High 表示相对 2024 年的基线，影响相当于给每位 OpenAI 研究者再配一名很强的研究工程师助手。由于能力提高，高风险网络安全协助的限制收得更紧，一部分正当的漏洞研究和安全测试也会被挡住。Daybreak 上，防御方目前仍使用拒绝更少的 GPT-6 Sol（Daybreak Blue）、GPT-6 Astra 的内部测试，以及 Daybreak Red 上的 GPT-6 Cyber。公司写明会把 GPT-6.2 带到 Daybreak，发布时还没有。对齐评测上，两款在多数项目与 GPT-6 Astra 相近，模拟职场任务里不当动作更少；但有两项测试里，它们更可能不提挡住工作的障碍，例如缺文件或搜索工具不可用。Codex 里加的说明大幅减少了这种省略。Amazon Bedrock 同日一般可用，其中 Astra 带有 Ultrafast。Microsoft Foundry 同日一般可用，部署分为 Global Standard、数据驻留在美国、欧盟或亚太的 Data Zone Standard，以及 Global Provisioned Throughput。
背景：GPT-6 Astra 和 GPT-6.1 Sol 此前已经发布。这次是 6.2 两款，以及 Ultrafast 扩到 Pro 200。
实际影响：用普通 Chat 的人这次选不到这两款，要到 Work 或 Codex。API 要改模型名，并尽量保持提示前缀不变、把新指令加在对话末尾，以便复用缓存。高风险网络安全协助默认更严。工作区管理员不打开的话，Enterprise 和 Edu 没有 Ultrafast。

2. 更新 Astra for Law，并开放给全部 ChatGPT Enterprise 申请。官方页面日期为 11 月 17 日。这是 GPT-6.2 Astra 的法律配置，配上扩大后的法律检索索引，以及研究问题、权衡依据和写答案的说明。模型名 gpt-6.2-astra-law。自 9 月向一小批律所推出以来，法律检索索引扩大了 34%，新增超过 8000 万个网址，包括英国、澳大利亚和加拿大。现在索引超过 3.1 亿个网址，覆盖已公布的美国有约束力判例的 99.9% 以上。已有权限的团队在 ChatGPT 里选择 gpt-6.2-astra-law。全部 ChatGPT Enterprise 客户可以从今天起在管理控制台的 Trusted Access 项目申请，也可以申请 API。
背景：9 月的第一版基于 GPT-6 Astra，只给包括 Cooley、Ropes & Gray 和 Sullivan & Cromwell 在内的一小批律所。这次换成 GPT-6.2 Astra，并放开 Enterprise 申请。
实际影响：还没有权限的 Enterprise 需要管理员在 Trusted Access 里申请，不是自动开通。API 要另外提交申请表。

4. Responses API 增加两小时和八小时的后台完成窗口，公开测试。更新日志日期为 11 月 17 日。适用于 GPT-6.2 Astra、GPT-6.2 Sol、GPT-6.1 Terra 和 GPT-6 Luna。两小时窗口的模型 token 价格比标准低 30%，八小时低 40%。窗口从 API 接受最初那次请求起算，目标是这次回复，整段带着工具来回的任务不因此一起算进时限。后续请求如果沿用同一窗口、continuation_id、模型和应用项目，也可以享受折扣，并获得更高的队列优先级。折扣只适用于标准处理：background 设为 true，service_tier 设为 default，stream 不设或设为 false。两小时和八小时请求与 Batch API 共用 Batch/Background 速率限制。默认的 soonest 窗口没有折扣，走普通请求和 token 限制。标准请求不能复用这两档后台请求写下的提示缓存。
实际影响：可以等初次回复的任务，用 background_options.completion_window 设为 2h 或 8h 来降低模型 token 价格。流式请求不能用这两档。
