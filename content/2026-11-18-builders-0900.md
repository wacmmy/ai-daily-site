Tibo / Sam：GPT-6.2 Sol 与 Astra 上线，Sol Ultrafast 扩到 Pro 200
1. Thibault Sottiaux（@thsottiaux，Codex 与 ChatGPT，OpenAI）发帖：「GPT-6.2 Sol & Astra are *finally* here。」他写，Sol 的 Ultrafast 已扩到 Pro 200 套餐，这是他日常大多数事情的主力模型；随后又补了一句，这些模型非常省，体感会落在完成任务的速度、费用，以及同样用量能多干多少活。Sam Altman（@sama）引用该帖宣布「6.2 Sol and Astra are out」，称它们能做很了不起的事，而且很省 token；他特别点名 6.2 Sol ultrafast，认为大家会喜欢。紧接着他又说：虽然新模型很聪明，但「让模型更好用」还有工作要做，接下来的版本会优先补这一块；即便要多花一点功夫，智力和能力本身已经非同寻常。OpenAI 官方博文（标题 Introducing GPT-6.2 Astra and Sol）写：Astra 面向最难的项目，Sol 面向日常工作，两者都用更少的输出 token 完成更吃力的任务。即日起，ChatGPT Work 和 Codex 向所有 Plus、Pro、Enterprise 和 Edu 用户开放；Pro 500 订阅者可对两个模型使用 Ultrafast；Pro 200 首次获得 Ultrafast，先从 GPT-6.2 Sol 开始；Enterprise 和 Edu 需工作区管理员打开后，符合条件的用户才能用。API 模型名是 `gpt-6.2-astra` 和 `gpt-6.2-sol`，两个模型发布时都可以用 Ultrafast。Astra 的 API 输入、输出单价比 GPT-6 Astra 低 20%，缓存输入再打 60% 折，标准价为每百万 tokens 输入 8 美元、缓存输入 0.40 美元、输出 40 美元；Sol 沿用 GPT-6.1 Sol 的价格：输入 2 美元、缓存输入 0.10 美元、输出 10 美元。官方还给出一组对比：在 Agents’ Last Exam 上，GPT-6.2 Astra 比 GPT-6 Astra 高 5.2 分、费用不到其三分之一，比 Claude Fable 5.2 高 5.5 分、费用约为其 5%；博文脚注写，该榜上 Fable 5.2 的成绩排除了 9 道使用了后备模型的题。
背景：Sol 和 Astra 是 GPT-6 系列里日常与高难两条线，此前已有 6 和 6.1；这次官方主打的是专业输出和单位费用，而不只是再报一条「更强」。
实际影响：有 Plus 或 Pro 的人可以在 ChatGPT Work 和 Codex 里直接改用；Pro 200 用户第一次能用上 Sol 的 Ultrafast。走 API 的人可改 `gpt-6.2-astra` / `gpt-6.2-sol`，Astra 比 6 Astra 更便宜，Sol 价格没变。
社区讨论：发布后 X 上出现大量负面评价。Tibo 回复称，这在各个层面都是一次相当好的跃升，而且更便宜、更快，团队会继续把各层做对。有早期测试者认为问题出在 harness（有人点名 Codex），拿掉之后手感就起来了——这是测试者的经验，不是官方结论。Peter Yang 没有拿到提前体验，根据时间线上的反馈认为「看起来没错过太多」，这是他的判断。Guillermo Rauch 称这是「全球最擅长网络安全的模型」，并指出 Vercel 的 DeepsecBench 是实验室事先拿不到代码库的隐蔽基准；具体名次以榜单页为准。Every 的系统测评见下一条。

Amjad：Replit 推出 Missions，用有预算上限的 agent swarm 去完成给定目标
3. Amjad Masad（@amasad，Replit）发帖：模型最近更自主了，但你给一个目标时，它们常常理解偏、漫无目的地干、把 token 浪费掉。今天推出 Missions，他称为「世界上第一个 agentic swarm harness」，可以在你设定的预算内完成任意目标，并举例「先帮我拿到前 10 个客户」。官方博文写：你定义结果，Replit 调度一组 agent 去规划、构建、测试和迭代；启动时会问清楚怎样算成功，并在协议里设定花费上限、哪些动作必须经你批准。进行中可选择立即、每日或每周接收阻滞和进度；独立的 AI 评委按约定标准验收，达标才算完成，预算先花完则停在未完成状态。Replit 自己用 Missions 做了可私有化部署的监控平台 DataCat：两天、预算上限 3,000 美元，做出了看板、告警和链路追踪；他们故意植入一个数据库故障，DataCat 在 38 秒内告警（目标是 60 秒），并定位到具体查询。三小时压测写入 2,600 万条活动记录和 440 万条日志，零丢失，51 项正确性与告警可靠性检查全部通过。在 13 项 NumPy 优化任务上，Auto（Max）配置下，1 个 agent 最高约 4 倍加速，16 个约 17 倍，32 个约 19 倍。
背景：这是把「多 agent 并行试错」收成一个带预算和审批的产品，而不是再发一个普通的编码 agent；和近期大家讨论的 swarm、后台 agent 是同一方向。
实际影响：有可量化目标、又能接受花费上限的团队可以直接在 Replit 上试，例如「拿下前 10 个付费客户」或「自建一套监控」。对外联络、改销售材料或做产品承诺这类动作，可以事先设成必须审批。

Peter Yang：与 Satya Nadella 访谈的五点摘录，核心是「人人带 token 预算」和「别绑死在一个模型上」
5. Peter Yang（@petergyang）发帖：离开微软 13 年后，他在 Ignite 访谈了 Satya Nadella，并把五点回答略作整理后公开。关于微软能不能追上前沿实验室，Satya 用当年 Azure 追亚马逊的问题作比：世界会需要不止一块云、也不止一个模型，客户要的是灵活性与可选项，同时按任务拿到所需 token、并考虑经济性。关于人们对 AI 改变工作的焦虑，Satya 说他的工作是把焦虑变成重组微软，让它看起来像一家新公司：创始人有一份 token 预算，招来的人也有；所有 IC 都将成为带着 token 预算的 agent 管理者。他举例：Copilot Cowork 由 11 名开发者做成，GitHub Copilot 运行时由一名开发者维护。关于软件若主要为 agent 而建，他说现在所有业务应用都成了 Copilot 的无头插件，因为 agent 全天候在用，使用量不降反升；他自己的 Autopilot 每天从 OneNote 和会议里取上下文，再去 Dynamics CRM 和供应链系统核对，形成以前做不到的 360 度视图。关于模型是否越聪明越安全，他说曾经以为对齐会随规模涌现，按经验结果「maybe not」，所以需要一套独立于模型的信任架构，因为责任在公司这边，他喜欢把这比成内部人风险。关于如何避免锁进一个模型：假定下一次模型更新会迫使你重新规划，不要围着某个模型建成压舱石；他想把模型业务做成类似数据库的生意——用模型，但上面建的是你的；记下 agent 的 traces，用来微调，下次升级后再微调，继续往前走。
背景：这是一场 Ignite 期间的访谈摘录，不是产品发布；Satya 把「token 预算」和「业务应用变成 agent 的插件」说成微软内部正在推的组织形态。
实际影响：做企业 AI 规划的人可以直接对照这五条：给人和团队配 token 预算、把业务系统做成可被 agent 调用的无头接口、把信任架构和模型分开，以及不要为某一个模型做过多绑定。这些是 Satya 的表述，不是已经完成的全公司现状说明书。

Claude：Platform 上线 linked billing 公测，第三方平台不必再经手客户的 API key
6. Claude 官方博客 11 月 17 日发文，介绍 Claude Platform 的 linked billing（公测）。第三方平台（如编码 agent、工作流自动化工具）可以让终端客户为 Claude API 用量付费，而不再分享 API key。客户把已有的 Claude Platform 组织关联上去，用量直接记到该组织，平台侧不再保存、加密或轮换客户的 key；客户为每个平台批准关联、设定支出上限，并可随时取消。平台负责发请求，Anthropic 向终端客户收款；平台可按请求选择由平台付还是由客户付，也可在 Console 或 Usage and Cost Analytics API（公测）里查看每个关联客户的请求数、token 和所用模型。组织里 Owner、Admin 或 Billing 角色批一次，整个组织生效。请求跑在平台的组织里，因此客户组织里的 IP 允许名单、加密密钥和数据保留等设置并不自动适用。文中列出目前已支持的平台，包括 Asana、ClickHouse、Factory、Gumloop、Harness、Higgsfield AI、Kilo Code、Linear、Major、Mintlify、Omni、OpenArt、Niteshift、Railway、Ramp、Runlayer、Tessera、Tines 和 Warp。第三方可在 Console 创建应用并按文档接入；客户可从支持的平台发起关联，也可在 Claude Marketplace 里找到这些平台。
背景：以往在第三方里用 Claude，通常要把 API key 交给对方，等同一把密码；这是官方提供的「关联组织、不交钥匙」替代方案。
实际影响：用 Linear、Railway、Warp 等已支持平台的人，可以用已有的 Claude Platform 组织和承诺用量直接开通，并给每个平台设月度上限。平台开发者若还在收集客户 key，可以按文档改成 linked billing。要注意请求跑在平台组织里，客户侧的网络和数据保留策略不会自动跟着走。

Guillermo：给 agent 加上 modern-web-guidance，对着真实浏览器检查页面体验
7. Guillermo 引用 Vercel Labs 的 Chris Tate（@ctatedev）的帖子，称「Actually a huge deal for web performance」，并说 `agent-browser vitals` 很聪明，「self-optimizing software is here」。Chris 介绍的新 skill 叫 modern-web-guidance：agent 会查阅 Chrome 的 Modern Web Guidance，应用到你的代码上，再在真实浏览器里检查结果，覆盖布局偏移、减少动态效果、暗色模式、对话框焦点等。起步命令是 `npx skills add vercel-labs/agent-browser`。
背景：这是把浏览器里的体验规范收成一条可安装的 skill，让 agent 改完就能自己验收，而不是只在代码里「看起来像」做对了。
实际影响：已经在用 agent 改前端的人，可以直接装这条 skill，让它按 Chrome 的现代 Web 指引检查，而不是只看截图或本地预览。

Garry Tan：公开 methodology-appendix skill，让别人的 agent 也能复现你的分析；GBrain Hosted 支持个人–团队–公司记忆层级
8. Garry Tan（@garrytan）发帖：他常把 PDF 和 Markdown 发给同事，对方也会用自己的 agent 来理解这些材料，于是做了 methodology-appendix 这条 skill，确保别人的 agent 能复现他的 agent 得出的结论。规则是：凡结论建立在数据查询上的报告、PDF 或页面，文末必须带一份「Replication Appendix」，检验标准是「一个有 agent、并有同等数据权限的读者，只凭附录就能从头生成这份文档，而不用再问作者」。正文只写结论，过程放到附录；附录固定六段：所需权限和快照日期、关键指标如何选取及换一种定义会怎样改变结论、可粘贴的原始查询、带命名常数的推导、从源文件生成并目视检查 PDF 的命令，以及数据会漂移之处、覆盖缺口和已撤回的主张。分析备忘、给外部看的 PDF、有定量结论的页面都默认加上，叙事性文字和会议记录则跳过，而且不必事先询问。同日他还介绍，GBrain 的 Hosted 方案开箱即支持「每个员工的个人记忆接到团队记忆、再汇总成公司记忆」，说明页在 gbrain.io/memory/topologies。另外他预告未来几周会用 Vorflux 做软件工厂，把 GBrain 后端改成 Rust，用来替换 postgres+pgvector 或 pglite，承担向量检索、图检索、嵌入、RAG 和 HNSW；有人问到现有数据时，他回复「we'll keep postgres as an engine」。
背景：11 月 14 日简报写过他公开的 Idea Miner skill，那是「根据近两天记录排出下一步该做什么」；这次是另一条可复制的 skill，解决的是把分析交给别人的 agent 之后还能被复现。Hosted 的层级记忆和 Rust 后端是产品侧的补充，Rust 引擎尚未上线。
实际影响：经常把带数据的备忘录或 PDF 发给同事的人，可以直接按他公开的六段结构写进自己的 skill。已经在用 GBrain Hosted 的团队，可以按官方拓扑把个人、团队和公司记忆接起来；Rust 后端还在预告阶段，现有 Postgres 引擎他称会保留，迁移细节以官方后续说明为准。
