GPT-6.2 Sol 开始进入 Chat 标签。帮助中心发布说明的日期是 11 月 23 日。ChatGPT 账号于上海时间 11 月 24 日 03:04 发帖。The Verge 于 UTC 11 月 23 日 20:47 报道，合上海时间 11 月 24 日 04:47。正在全球推出一版面向 Chat 标签、做日常对话的 GPT-6.2，套餐是 Plus、Pro、Business 和 Enterprise。Enterprise 是否看得到，取决于工作区管理员设置。这版由 GPT-6.2 Sol 驱动。Work 和 Codex 用的模型这次不改。它更会处理带详细指令的复杂请求，也更会上网找信息。比较周末酒店时，可以按价格和地点取舍。问某样东西是否在打折时，可以提出价格下降后再提醒。发布说明里的 Chat 测试：图像理解 71.7%，GPT-6 是 47.4%。特别难的指令跟上的比例 78.1%，GPT-6 是 62.5%。他们测过的最低推理档上，内部专家任务 65%，GPT-6 是 52%。内部版 BrowseComp 在 Extra high 为 64.5%，GPT-6 是 54.4%。困难对话里符合安全政策的比例 91% 到 94%，GPT-6 是 77% 到 80%。
背景：11 月 18 日简报写过，GPT-6.2 Sol 和 Astra 只在 ChatGPT Work 和 Codex，普通 Chat 不含这两款。这次新的是 Chat 标签里这版面向日常对话的 Sol。
实际影响：发布说明点名的是 Plus、Pro、Business、Enterprise，而且写的是开始推出，不是四档同时全部打开。Enterprise 要等管理员设置。Work 和 Codex 里原来的模型选择这次不变。

2. 与 Cisco 开源 Shirudo。官方页面日期为 11 月 23 日，官方账号于上海时间 11 月 24 日 05:37 发帖。这是一个开源 Linux 运行时，让团队在补丁还在测试和上线时保护正在跑的系统，不必为了加上这层防护而重启。临时防护叫 shield。操作员可以先看它会不会误伤正常请求，批准之后再加载，服务继续跑。实现用的是 eBPF。加载前会核验密码学签名，并由 Linux 的 eBPF 校验器检查。TPM 用来留下防护被加载或卸下的记录。受控测试里，用 Codex 生成的一道 shield 给正在跑的 Elasticsearch 加上输入检查，挡住了一次 Java4Shell 利用，服务没有重启。许可是 BSD 2-Clause，BPF 程序同时用 BSD 和 GPL。
背景：页面写，找到漏洞和把补丁铺到每台机器之间往往还要几天到几周，而这层防护就是给这段时间用的。
实际影响：仓库写明目前是 pre-release。生产目标需要带 signed-loader ABI 和 Shirudo 内核补丁的 Linux，以及 TPM 2.0。防护要操作员批准后才会加载。
https://openai.com/index/introducing-shirudo/
https://github.com/shirudo-dev/shirudo

5. 推出 Claude Ship，公开测试。文章日期为 11 月 23 日。它处理 GitHub 上的拉取请求，分成已正式可用的 Code Review，以及两个新的测试版智能体 PR Steward 和 Claude Approvals。PR Steward 处理失败的 CI、合并冲突，以及 Code Review、其他评审工具或团队成员的反馈。每次推送后它会说明改了什么、如何撤回。它被设计成不批准、也不合并。开发者可以用 @claude 加指令来引导，或用 @claude stop 让它停下。Claude Approvals 读取仓库里的策略文件，策略允许时可以自行批准常规改动，也可以要求人工再签。文章建议多数客户先开只观察模式，再让分支保护把 Claude Approvals 的通过作为必需检查。开发者可以在 Claude Code 里用新的 /ship。管理员按仓库打开 Code Review 和 PR Steward，并选择 Quick、Standard 或 Deep，以及何时评审、花费上限。Claude Approvals 在默认分支上有策略文件时启动，管理员可以关掉。
背景：Code Review 本来就已经正式可用。这次新的是 PR Steward、Claude Approvals，以及 /ship。
实际影响：可用范围是 Claude Team 和 Enterprise，仓库要在 GitHub。零数据保留、HIPAA 配置或客户自管加密密钥的组织不能用。用量按 token 计。管理员可以给 Code Review 和 PR Steward 设花费上限。Claude Approvals 没有基础费用，策略里的分类器按 token 计费。策略如果调用 Claude 的评审，即使在只观察模式也会触发一次计费的 Code Review。/ship 算进普通 Claude Code 用量，并且从今天起在 Claude Code 和桌面应用里推出。符合条件的 Enterprise 可以领取至少 10000 美元 Claude Ship 额度，领取后 30 天内使用，领取截止 2027 年 1 月 15 日。

7. 零数据保留下的 Enterprise Frontier Safeguards 进入公开测试。Claude 账号于上海时间 11 月 24 日 02:15 发帖。EFS 在多次请求之间查找滥用，同时兼容零数据保留。输入和输出写到客户自己的存储之后，Anthropic 和云厂商都不保留副本，人员也不查看这些输入和输出，也不拿去训练。发现风险时生成 Safety Case，可以从客户的云存储或 API 读取，接进安全信息和事件管理系统，里面不含输入和输出。客户可以用自己账号里的 Amazon S3 或 Google Cloud Storage，云厂商照常对存储计费。平台发布说明同日写，公开测试开在 Claude Platform、Claude Platform on AWS，以及 Google Cloud 上由 Anthropic 托管的 Claude 模型。文章还列出 Amazon Bedrock 和 Claude on Google Cloud，并写 Microsoft Foundry 即将支持。符合条件的客户会收到开通说明。同一天的发布说明还给组织 webhook 加了两个测试版事件。客户自有存储的桶如果没通过每日检查，发送 external_storage.failed，恢复后再通过就发送 external_storage.recovered。
背景：文章写 EFS 在 9 月已经宣布，之后与 100 多家客户继续做，其中包括财富 100 强里的四分之一，非公开测试里有 Bridgewater、Salesforce 和 Stripe。这次新的是公开测试。
实际影响：文档写 Anthropic 不对 EFS 收费，模型行为、API 价格和速率限制也不因此改变。存储费用由云厂商向客户收。它覆盖已配置工作区里的 Messages API 请求，不覆盖代码执行容器、Files API 上传、Batch API 结果和 Claude Managed Agents 会话各自存下的数据。还没收到开通说明的组织，现在还不能自行打开。
