今日要点：11月15日14:00起，火山方舟开放豆包 Seedance 2.5 Flash 的在线体验和 API，模型 ID 为 doubao-seedance-2-5-flash-261115，只出 480p 和 720p，不支持样片。混元 HyFF 升到 0.3.0，可以接入 ASE，并在已发布权重上按自有能量和力微调。Hy Memory 2.0.17 给已有 Qdrant 集合补上显式的 BM25 升级，PyPI 仍是 2.0.16。

字节豆包
Seedance 2.5 Flash开放在线体验和API
火山方舟写明，北京时间11月15日14:00起，Doubao Seedance 2.5 Flash 正式开放在线体验和 API。发布记录里的模型 ID 是 doubao-seedance-2-5-flash-261115。它支持文生视频、首帧和首尾帧、全模态参考、视频编辑和视频延长，也可以出有声视频。单次时长 4 到 30 秒，也可以传 -1 由模型选择。参考上限是 10 张图、5 段视频、5 段音频。输出分辨率只有 480p 和 720p，格式为 mp4 或 mov。不支持样片模式，离线推理暂不支持。
背景：旗舰 Seedance 2.5 的模型 ID 是 doubao-seedance-2-5-260628，支持样片，参考上限是 30 张图、10 段视频、10 段音频，并可以出 1080p。11月13日更新的教程页已经公开 Flash 的模型信息和价格，并把在线体验、API 的开放时间写在 11月15日14:00。这次新的是到点可以调用。
实际影响：价格页上的名称是 doubao-seedance-2.5-flash。480p 和 720p 的在线单价相同：输入不含视频每百万 token 46 元，输入包含视频 28 元。不含视频、16:9、输出 5 秒的示例价是 480p 约 2.21 元、720p 约 4.97 元；同条件旗舰 720p 的示例价是 7.56 元。只对成功生成的视频计费。开通需要账户余额大于 200 元，或购买 200 元档及以上专属节省计划，或持有仍有余量的 Seedance 2.5 系列资源包。Flash 另有资源包，7M token 刊例价 196 元、10M 为 280 元、100M 为 2800 元，有效期 90 天，不能用旗舰包抵扣。

腾讯混元
HyFF 0.3.0可以接入ASE，并在已有权重上微调
11月15日00:30，混元把 HyFF 升到 0.3.0。新增 ASE 计算器 HyFFCalculator，可选依赖 ase。孤立体系或周期性体系都能算能量和力，总电荷和自旋多重度从 atoms.info 的 charge、multiplicity（或 spin）读取，还不能算应力。CUDA 上重复评估同一体系时沿用编译好的引擎，换一批不同结构可以用 eager。微调从已发布权重起步，读扩展 XYZ 或 NPZ 里的参考能量和力；训练前用最小二乘重拟合每种元素的能量偏移，因此可以换成另一套电子结构方法的数据。可以按名字冻结参数、做权重的指数滑动平均、保存检查点并续训，同一台机器上用 --gpus 做数据并行。导出的权重要用 hyff.load(weights=...) 加载，快速引擎、Simulation、predict_batch 和计算器都能跑。同一大小的结构在周期和孤立之间切换时，eager 邻接表现在会重建。
背景：权重发布 hyff-v0.2.0 没有改。说明里写，现有 NVE、NVT、NPT 和推理的结果与速度保持不变；2586 原子、1 飞秒的 NVE 速度相对 0.2.0 变化在 1% 以内。
实际影响：已经在用 HyFF 做分子动力学的，不用换权重。要做几何优化或单点能，安装可选的 ase 后把 HyFFCalculator 挂到 atoms 上。要用自己的能量和力微调，运行 hyff finetune。用 ASE 驱动分子动力学时，每步都要在 CPU 和 GPU 之间传递位置和力；生产模拟仍用 hyff.Simulation。

Hy Memory 2.0.17给已有Qdrant集合补BM25，不会自动执行
11月15日16:49，Hy Memory 主分支记为 2.0.17，更新日志署期 11月14日。Qdrant 的 BM25 维护改成显式操作。plan_qdrant_bm25_upgrade() 会报告集合是只有稠密向量、缺稀疏向量，还是稀疏修饰符不兼容。upgrade_qdrant_bm25(writers_stopped=True) 用 Qdrant 的命名向量 schema 接口，按有界批次只回填派生的 bm25 向量，跳过原始对话行，稠密向量和用户 payload 都保留。重复执行是幂等的。空文档或零 token 文档用私有 payload 状态标明覆盖范围，不塞可搜索的占位词。新集合会声明 FastEmbed 的 Qdrant/bm25 所需的 IDF 稀疏修饰符。schema 或点覆盖不完整时，启动不会把关键词通道当成已经就绪。
背景：11月13日简报里的 MemHub 1.0.7 仍基于 hy-memory 2.0.16。PyPI 上的最新包到这次核对时仍是 2.0.16，上传时间是 11月12日。更新日志写明，这是只在 SDK 里的维护接口，正常启动和 MemHub 的 Runtime、CLI 都不会自动跑，产品打包和入口还要另做。
实际影响：从 PyPI 安装的 2.0.16 还没有这个升级接口。要用的话，需要主分支上的 2.0.17，并在写端停止后自己调用 upgrade_qdrant_bm25。不支持的客户端或缺少 FastEmbed 时，会返回结构化的阻塞状态，而不是把迁了一半的集合当成可用。
