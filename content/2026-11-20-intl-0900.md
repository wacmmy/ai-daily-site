1. GPT-Live-1.1 已在 API 上线。更新日志日期为 11 月 19 日，开发者账号于上海时间 11 月 20 日 04:00 发帖。模型名 gpt-live-1.1，只支持 v1/live/sessions。相对 GPT-Live-1，转写更准，跨语言的口音和声音更一致。开发者用自然语言说明何时把任务交给后端做推理或工具调用。同一条更新写，可以为 GPT-Live-1 和 GPT-Live-1.1 的 WebRTC 会话配置 standby，在推理暂停时降低费用。模型页写，活跃会话每分钟 0.05 美元，standby 每分钟 0.02 美元。后端模型和工具另计。两款模型的并发会话上限分开计算。
背景：9 月 10 日的更新日志写过，GPT-Live-1 在 API 正式可用，语音会话按每分钟 0.05 美元计费。这次新的是 1.1，以及 WebRTC 的 standby。
实际影响：Chat Completions 和 Responses 都不能调用这款模型。空闲时把 WebRTC 会话设为 standby，分钟价格从 0.05 美元降到 0.02 美元。

2. 公布用 Codex 保持 ChatGPT 性能的 Performance Factory。官方文章日期为 11 月 19 日，开发者账号于上海时间 11 月 20 日 01:42 发帖。这是跑在云上的内部系统。工程师用配置和提示定义工作流，调度循环把就绪的步骤交给 Codex。第一条工作流叫 Regression Workflow：性能告警会打开任务，智能体调查变慢的原因、记下发现，并提出修复供工程师审核。部署之后，另一个智能体检查性能是否回到基线。任务的状态和发现记在单个智能体的上下文之外，以便交接。三个多月里，这条工作流跟踪了超过 1700 次调查，找到超过 600 次根因，大约每天 17 次自动调查。系统还有订阅，在 GitHub 评审评论或部署完成时再把智能体叫醒。诊断会经过另一场 Codex 会话的对抗式复核，用来检验站不住的解释。
实际影响：没有新的对外开关。提出的修复要工程师审核后才会部署。
https://openai.com/index/how-openai-performance-factory-keeps-chatgpt-fast/

Claude Code 2.1.329 发布。发布时间是 2026-11-19 22:14 UTC，合上海时间 11 月 20 日 06:14。信任对话框会写明一个文件夹的钩子声明在哪里。Claude Desktop 和其他非交互宿主里，托管设置中的钩子加载失败时，对话中会给出警告。/tasks 现在列出这次会话的计划任务、/loop 唤醒、目标和这条对话的分叉，x 会先询问再停掉其中一个。/mcp 里远程 HTTP 服务器拒绝连接时，会显示 JSON-RPC 错误。/status 会点名哪些受托管的市场不会自动更新，以及原因。打开 OpenTelemetry 事件和指标时也可以打开 Code Mode，代码发起的每次工具调用都会发送事件；追踪仍然会把 Code Mode 关掉。同版修了几处会丢掉状态的问题：网络卡住或文件锁让 ~/.claude.json 读不出来时，保存不再把它清成默认。macOS 上能读钥匙串但写不进去时，不再反复登出；该会话会在到期时停下并说明原因，其他会话保持登录。/teleport 里挑选云端会话不再替换当前对话，而是像 /clear 一样新开一条，/resume 可以回到原来的。Pro 和 Max 在打开浏览器后，/usage-credits 不再要求重新登录。/usage 不再把额度用尽或达到月度上限说成额度功能已关闭。Code Mode 里失控循环会在达到内存上限时被停下。

13. Gemini API 推出 Tool Retrieval 预览。官方博客和更新日志的日期都是 11 月 19 日。在 Interactions API 里加入 tool_search，并把想暂缓加载的工具标成 defer_loading 为 true。模型仍能看到每个延后工具的名称和描述，参数 schema 先不进入上下文。需要时，模型按名称索取，API 在同一次请求里载入完整 schema 再调用。远程 MCP 服务器也可以延后加载。没有单独的费用。打开 tool_search 会增加一小块固定的输入 token，载入的 schema 在之后的对话里按输入计费，和一开始就声明的工具一样。适用于 Gemini 3.6 及之后的模型，包括全部 Gemini 4 模型。
实际影响：工具很多、多数 schema 不会被用到时，输入 token 才会降下来。常用工具仍可以先加载，只把长尾延后。
