Claude：把常用 artifact 安装成 Mac / Windows 应用
1. Claude 官方文章标注日期为 11 月 24 日，宣布在 Claude for Mac 和 Windows 里以 beta 推出「Install as app」：可以把 artifact 安装成独立桌面应用，拥有自己的图标和窗口，不必再开在 Claude 里边。安装后的应用可以使用 Claude 和你的 connectors，底层 artifact 被编辑后会自动更新；应用向 Claude 发出的请求计入当前方案的用量上限。应用可以发通知，或出现在菜单栏 / 系统托盘。权限分三档：Default 只能做浏览器里也能做的事；App permissions 可申请置顶窗口、全局快捷键、通知等由 Claude 控制的能力；Full computer access 可申请在不逐次询问的情况下运行程序、读写或删除文件。完整电脑权限只适用于你自己做的应用，或 Team / Enterprise 里本组织成员做的应用；授权只覆盖当前版本，自己改过或更新后也会再问一次。Anthropic 不在安装前审查这些应用，文章提醒只把完整权限给自己信任的应用。若应用有一部分来自其他网站，那一部分可以在 Claude 不再询问的情况下发生变化。开始方式是：更新 Claude for Mac 或 Windows，打开常用 artifact，在 Share 菜单里选「Install as app」。不必打包或签名，用的是你的 Claude 账号，没有单独的 API key 或登录。该功能正在所有方案以 beta 滚动推出；HIPAA-ready 组织和混合部署不能用。Team 默认打开，但完整电脑权限默认关闭；Enterprise 默认关闭，需由 owner 打开。打开应用时需要在线并登录 Claude。Claude Docs、Slides 和 Sheets 等部分 artifact 不能安装。文中列举了 Anthropic 内部用它做的例子，包括图像编辑器 Linnet、文件管理器 Phosphor、整理文件的 Sift、带 Claude 的终端 Tern，以及查看电脑性能的菜单栏应用 Vitals。
背景：Artifact 最早是聊天里可分享的图表或网页；后来有人把它当成日常工具，例如从日历和邮件拉材料的会前页。这次是把它做成系统里能单独打开的应用。近 7 天 Builders 简报没有报过「Install as app」。
实际影响：更新 Claude 桌面应用后，可以把已经在用的 artifact 从 Share 菜单装到本机。Team 用户默认就能装，完整电脑权限是关的；Enterprise 要等 owner 打开。有 HIPAA 或混合部署要求的组织现在还用不了。
https://claude.com/resources/articles/install-as-app

Claude：MCP 服务器可随工具发布 skills，Tasks 和 Elicitation 正式可用
2. Claude 官方同日发文：Skills over MCP 已在 Claude 里进入公开测试，MCP 服务器可以在提供工具的同时发布 skills。Claude 只在需要时加载相应 skill，以降低上下文占用；skills 随服务器更新，用户不必再单独安装一份说明。文章举例：Shopify 用它帮 Claude 端到端设计和更新商家网店，HubSpot 用来做客户开通，Atlassian 用来调用组织上下文做分析和工作梳理，Carta 计划用来根据上传文档起草和发放股权（即将推出）。Skills over MCP 在 Claude 和 Claude Code 里公测，Pro、Max 和 Ultra 默认打开，Team 需管理员开启，Enterprise 即将推出。同一篇文章还宣布：Tasks 和 Elicitation 已在 Claude 和 Claude Code 对 Pro、Max、Ultra 正式可用，并正在向 Team 和 Enterprise 组织滚动推出。有了 Tasks，服务器可以跑耗时操作甚至完整的 agent 循环，Claude 先继续手头工作，完成后再取结果；文中举例 ZoomInfo 用它做以往要分多轮提示的客户和联系人研究。有了 Elicitation，服务器可以在工具调用中途暂停，通过表单或链接向用户要确认，再从停下的地方继续；举例包括 Supabase 在创建付费项目或执行破坏性 SQL 前确认费用，Railway 在移除服务等可能有破坏性的变更前询问，GitHub 在 agent 删除仓库前要求用户输入仓库名。File Uploads 扩展将让 Claude 把 PDF、表格和图片直接传给 MCP 服务器，而不经过上下文窗口；该能力即将在 Claude 和 Claude Code 向 Pro、Max、Ultra 以及符合条件的 Team 和 Enterprise 方案推出。这些能力属于开放 MCP 规范及其扩展，兼容的客户端都可以用，不只限于 Claude。
背景：此前 MCP 主要解决「接到哪些工具和数据」；skills 则更多是「怎么用这些工具把一件事做完」。这次是把二者接到同一台服务器上一起分发。近 7 天 Builders 简报没有报过 Skills over MCP，也没有报过 Tasks 和 Elicitation 正式可用。
实际影响：用 Claude 或 Claude Code 的 Pro / Max / Ultra 用户，现在就可以用已支持这些扩展的服务器。做 MCP 服务器或插件的人，可以把工作流写成 skill 随服务器发布，并用 Tasks 和 Elicitation 处理长任务和危险操作确认。Team 要用 Skills over MCP，需要管理员打开；File Uploads 还没到，以官方后续滚动为准。
https://claude.com/resources/articles/skills-over-mcp-tasks-and-more

Guillermo：fx 做成 CLI，是因为它是可嵌入的 libfx 的薄封装
5. Guillermo Rauch（@rauchg）在 11 月 25 日 4:05（上海时间）发帖：fx 在现在还做成 CLI，主要是因为它是 libfx 的一层薄封装。目标是做出「最小、也最聪明的 coding agent kernel」，并能嵌到各种界面上：浏览器、服务器、移动端、桌面、操作系统和 ADE。他指向 fx 的网站。网站介绍 fx 是很小的开源原生 coding agent，CLI 用 Zig 写成，面向研究和作为更大系统的可嵌入部分。有人问能不能把 libfx 当 Eve 框架的内核时，他回复：libfx 现在更专注于写代码，「We definitely want to integrate these over time」。另有人提到即将推出的 Aerolite in Powermove V2 会用基于 libfx 的 harness，他回复「Cool」；有人说 fx 很小，并且可以和 Noodle 一起用 GLM、Kimi 等模型，他回复「More to come!」。
背景：fx 是 Vercel 这边的轻量 coding agent。这次他把「外面是 CLI、里面是可嵌入的 libfx」说清楚了，重点不是又发一个命令行工具。近 7 天 Builders 简报没有报过 libfx 这一层。
实际影响：已经在用 fx，或想在自己的界面、ADE、移动端里嵌 coding agent 的人，可以把 libfx 当成可嵌入的内核来看，而不只是把 fx 当成一个独立 CLI。和其他框架如何集成，以及「More to come」指向什么，还要等他后续说明。

Dan / Peter / Nan：Every 团队停用 Duet，转向 Dots；Dots 仍有稳定性问题
7. Dan Shipper（@danshipper）在 11 月 25 日 7:28（上海时间）发帖，称出现了 vibe shift：Every 团队里多数人已停用 Duet，「just not improving fast enough」，并认为 Dots 等竞品「very good」。他附了 Every 内部通讯《Why Duet didn't stick》的截图，并另帖指向 every.to 上的文章。截图里的事实是：大约一个月前，Dan 还在 Vibe Check 里说改用 Anthropic 的常驻 agent Duet「已经用起来了」，后来他又告诉团队自己其实不太用了，多数同事也是如此。文中的判断是：Duet 做的多是「表演性」工作，会在随机时间把任务翻出来，而不是替你把事情做完；有同事把它比作「针对我已经知道的工作事项的随机提醒」，而且它处在大家已经在用的应用之外。社交负责人 Becky Isjiwara 的看法是：Duet 只在 Claude 聊天里、不在 Cowork 或 Air 里，她不愿为了用它专门切空间；也不能在 Slack、iMessage 或 Air 里找它，所以她不用。她认为 Duet 也许能力更好，但 Dot 集成得更好，「更容易在我已经工作的地方伸手就用」。Every 现在的替代是：许多人继续用 OpenAI 的常驻 agent Dots；另一些人改用 Claude Code 里重新设计的 Projects——里面有一个协调 agent 按你设定的目标推进，这和 Claude 应用里只是文件夹的 Projects 不是一回事。企业 AI 采用负责人 Natalia Quintero 用新的 Projects 给每个 Claude Code 项目配自己的 manager agent，并用定时任务做重复工作；团队还用 Every Agent 管理全公司共享的上下文和 skills。文章的建议是：如果常驻 agent 主要是把工作递给你而不是替你做完，就换工具，或在你已经在用的工具里把 agent 当成项目经理。Nan Yu（@thenanyu）引用 Dan 的帖子，写了「DOT SUPREMACY」。Tibo 也引用该帖，只回了一个「👀」。
背景：昨天 Builders 简报写过，Tibo 称 OpenAI 内部 dots 正成为主要办事方式。Every 这次是外部团队的使用转移，不是 OpenAI 的产品发布。近 7 天 Builders 简报没有报过 Duet 被停用这件事。
实际影响：在选常驻 agent 时，可以同时看「会不会把事情做完」和「是不是开在你已经工作的地方」。已经在用 Dots 的人，下面这条稳定性反馈值得对照。
社区讨论：Peter Yang（@petergyang）在 11 月 24 日 10:55（上海时间）发帖，称 ChatGPT Dots「still feels very buggy」——会在他没有审阅的情况下发邮件，而且会突然停止响应；他想喜欢这个产品，但怀疑是不是自己提示词用错了。11 月 25 日上午，有人提起他先前对 Dots 的态度有变化时，他回复：「I think dots needs alot of work but the team is listening and hopefully will improve it fast。」前面是他作为使用者的具体故障描述，后面是他对团队响应速度的判断。

Tibo：Agents API 增加按 session 的预算控制和官方预热沙箱池
8. OpenAI 的 @AzianMike 在 11 月 25 日 4:09（上海时间）发帖，称 Agents API 新上了两件事。一是 Budget controls：可以按 session 限制、监测和控制 agent 预算，避免单个客户把 token 全部用完。二是 Pre-warmed pool of sandboxes：以前可以预热自己的沙箱，现在改由 OpenAI 管理一批已经预热好的、由 OpenAI 托管的沙箱，给对延迟敏感的任务用。Tibo 在 6:19 回复「Team is shipping」。
背景：这是 Agents API 的能力补充，针对的是用量失控和沙箱启动变慢，不是新的面向消费者功能。近 7 天 Builders 简报没有报过这两项。
实际影响：已经在 Agents API 上跑客户工作负载的人，可以按 session 设预算，并对延迟敏感的任务改用官方预热沙箱池。具体字段、额度单位和超出后的行为，以官方文档和产品界面为准。

Swyx：一份仍需人类工程师去做的 AGI 向问题清单
9. Swyx（@swyx）在 11 月 25 日 7:29（上海时间）发帖，注意到近期 Anthropic 以及从那里出来的人的演讲，都说得很具体：人类工程师要做的事还很多。如果因此感到焦虑，可以把力气转到他称为 AGI-aligned 的问题上。他列出的方向包括：先假定 multi-agent 系统放大 1000 倍，再看从拉起子 agent、当 LLM 评分器、顾问/搭档模式、记忆形成，到在一块板上点对点协作，哪些地方会坏掉；基础设施上，把 Kubernetes 拆开，做成新的文件系统、沙箱、有状态且能大规模编排的工作流（他提到 Temporal），「it's actors on steroids」；Agent 授权方面，他写大家都同意让 Instinct、Claude 等记住你的密码不好，也就是不该以「代表你」而不是「你把身份委托给 agent 自己」的方式采取行动，接下来还要解决 agent 之间如何互信；安全上既要加固和修补核心软件，也要在假定已被突破时限制爆炸半径；监测上要有只写的、跨 agent 的 OpenTelemetry 追踪，并接到不会把 agent 的持续运行误判成恶意行为的紧急切断。他强调这份清单并不完整。
背景：这不是产品发布，而是一份从近期演讲里整理出的、仍需有人去做的问题列表。近 7 天 Builders 简报没有报过这份清单。
实际影响：如果正在做 multi-agent、鉴权、沙箱、隔离或观测，可以把这份清单当作缺口对照，而不是只盯模型本身。
