Boris：Claude Ship 上线，评审、修复和按策略批准 PR
1. Boris Cherny（@bcherny）在 11 月 24 日 4:21（上海时间）发帖，宣布 Claude Ship 对 Team 和 Enterprise 以 beta 上线。他写：一年前他们发布了 Opus 4.5，第一次做到写完他全部代码，但合并 PR 的节奏没跟上；他现在整天都在用 Claude Ship，不再干等代码评审或盯着 PR。官方博客同日发布。Claude Ship 由已经正式可用的 Code Review，以及仍在 beta 的 PR Steward 和 Claude Approvals 组成：Code Review 查 bug；PR Steward 处理修复、失败的检查和评审意见，但设计上不负责批准或合并；Claude Approvals 按仓库里的策略文件，批准团队政策允许的变更。开发者可在 Claude Code 里对自己的 PR 使用新的 /ship 命令：Claude 会推送、开 PR、做评审，并处理反馈和失败检查；能否合并取决于开发者权限和仓库分支规则。/ship 从今天起在 Claude Code 和桌面应用滚动推出。Team 或 Enterprise 的管理员可按 GitHub 仓库打开 Claude Ship。Boris 建议先从一个仓库开始，并把 Approvals 开在 observe 模式，直到信任它再接到分支保护。合格的 Claude Enterprise 组织可在 2027 年 1 月 15 日前领取至少 1 万美元、领取后 30 天内可用的 Claude Ship 额度，条款适用。用量按 token 计费，管理员可为 Code Review 和 PR Steward 设置花费上限；开启了 Zero Data Retention、HIPAA 配置或客户托管加密密钥的组织不能使用 Claude Ship。
背景：这是把「写代码」之后的评审、修检查、按策略批准这一段自动化，针对的是 agent 已经能写大部分代码、但 PR 流程还靠人盯的落差。近 7 天 Builders 简报没有报过 Claude Ship。
实际影响：可以先更新 Claude Code 试 /ship。带 Team 或 Enterprise 的人，适合先选一个仓库、用 observe 模式看 Approvals，再考虑接到分支保护。有 ZDR、HIPAA 或客户密钥要求的组织现在还用不了。

Claude：connectors 与 skills 收成 plugins，个人方案已可用
2. Claude 官方账号（@claudeai）在 11 月 24 日 4:56（上海时间）宣布：把工具接到 Claude，或教它一项新 skill，现在是同一条路径。connectors 与 skills 收成 plugins，已在 Free、Pro、Max 和 Ultra 方案上线，Team 和 Enterprise 即将推出。目录可浏览 10,000+ 个插件。帮助中心同日更新：侧边栏原来的 Customize 改为 Plugins，用一个页面管理 plugins、skills 和 connectors，已安装的会保留。Team 方案从 2026 年 11 月 30 日起滚动上线，Enterprise 在随后几周。从 11 月 30 日起，如果组织关闭了 Skills，Claude Desktop 里的 plugins 也会被拦住，与网页版和 Claude Code 现在的行为对齐。

Claude：与 ZDR 兼容的 Enterprise Frontier Safeguards 进入公测
3. Claude 官方账号（@claudeai）在 11 月 24 日 2:15（上海时间）宣布：与零数据保留（ZDR）兼容的 Enterprise Frontier Safeguards（EFS）对符合条件的企业进入公开测试。它在多条请求之间查找误用模式，同时保持 ZDR。官方说已与 100 多家客户共同开发，其中含约四分之一的财富 100 强，以及医疗、金融服务和律师等对数据可见性要求很严的行业；9 月曾宣布过 EFS，此后进入私有测试，评估方包括 Bridgewater、Salesforce、Stripe 等。传统 ZDR 主要靠逐条请求的分类器；EFS 增加跨请求的自动安全监测，分析的是完全由客户控制的基础设施上的数据。发现风险时会生成供客户审阅的 Safety Case，可从客户云存储或 API 读取，并可接入 SIEM，其中不含输入和输出原文。客户自带存储（按使用的云，可以是自己账号里的 Amazon S3 或 Google Cloud Storage），用自己的密钥加密，并配置自己的访问策略。Anthropic 和云厂商在数据送达客户存储后不再保留副本，其人员不查阅输入输出，这些数据只用于自动安全监测，不用于模型或分类器训练。可用范围是 Claude Platform、Claude Platform on AWS、Amazon Bedrock 和 Claude on Google Cloud；Microsoft Foundry 的支持即将推出。符合条件的客户会收到启用通知。
背景：这是 9 月宣布后的公开测试，要解决的是「既要 ZDR，又要能做跨请求安全监测」的矛盾。昨天 Builders 报过 Guillermo 对「声称免费 ZDR 的 stealth 模型」的警告，那是另一件事，不是这次 Anthropic 的企业功能。
实际影响：有合规和 ZDR 要求的企业，可以等官方通知后评估 EFS，把日志放在自己的存储和密钥下，同时保留跨请求监测。这是符合条件企业的公测，不是所有账号默认打开。

Guillermo：Vercel AI Gateway 推出经独立审计的 Audited ZDR
4. Guillermo Rauch（@rauchg）在 11 月 23 日 21:39（上海时间）转发 Vercel 官方帖，并写：「ZDR you can actually trust」。Vercel 同日发布博客，在 AI Gateway 推出 Audited ZDR：只有经过独立安全公司对照源代码、基础设施和线上流量验证零数据保留声明、并公布报告后，供应商才会被标为 Audited ZDR。首发合作伙伴是 Baseten、Modal 和 Wafer，已开始审计，报告预计在 2026 年 12 月 8 日前公布。审计确认客户数据（提示词、补全、系统提示、嵌入、文件、音视频、工具调用载荷，以及可识别其身份的派生数据）不会被写入任何系统的持久存储；响应返回 AI Gateway 后，应从推理供应商系统中删除；KV cache 等只能在请求期间留在易失存储，且必须披露这一行为。审计还确认：标记为 ZDR 的请求不会故障转移到非 ZDR 端点、工具或功能；除处理请求本身外，不应有人或自动流程访问客户数据；有访问权限的子处理方同样遵守上述要求；不拿客户数据训练。Vercel 还在审计之间对供应商做 canary 监测：发送带有独一无二、未索引 URL 的提示词，若这些 URL 被访问，就对相应供应商和模型展开调查。canary 查不到「只写入磁盘、从未被读取」的情况，所以是补充，不能替代代码和基础设施审计。AI Gateway 政策设置将增加「经独立审计的 ZDR」供应商层级和团队级开关；打开后，路由和故障转移只走已公布达标报告的供应商。每个供应商在报告发布后进入该层级。
背景：昨天这期 Builders 刚报过 Guillermo 警告「免费、声称 ZDR 的 stealth 模型」，并预告 Vercel「明天」还会再提高信任和安全标准。今天落地的就是这次更新，是实质进展，不是同一条警告的重复。Vercel 今年早些时候已经上线团队级 ZDR 路由，并完成了 ISO/IEC 42001:2023 认证。
实际影响：走 Vercel AI Gateway 的团队，可以等 12 月 8 日前首发报告出来后，再打开只路由到 Audited ZDR 供应商的开关。在报告发布前，不要把这个层级当成已经可用来筛供应商。

Amjad：Replit 介绍 agent swarm 规模定律，Resonate 团队加入
6. Amjad Masad（@amasad）在 11 月 24 日 4:52（上海时间）介绍 Replit 关于 agent swarm 规模定律的研究。研究页标注日期为 2026 年 11 月 19 日，近 7 天 Builders 简报未报过，本轮补收。他和论文都写到：在固定的两小时窗口里，Claude Opus 5.5 单 agent 把 NumPy 工作负载加快了 3.7 倍，32 个 agent 的 swarm 达到 18.9 倍；GPT-6.2 Astra 是他们测到的最强单 agent，但超过 8 个 agent 后出现负向扩展。模型在没有被规定如何组织的情况下，会自发形成不同结构：去中心化的 swarm 扩展得更好，较好的一组较少靠直接私信，工作者在公共板上认领任务、分享结果；较差的一组把一切路由到协调者，收件箱随人数膨胀。问题是否容易并行，是预测 swarm 表现的强信号；单个模型的智力并不是集体智力的好预测指标。他们同时开源了 Optimization-Bench。同日 4:25，Amjad 欢迎 Resonate 团队加入 Replit，称他们带来持久化的 agent 基础设施经验，并且是他见过第一家带着 Lean 和 TLA+ 可验证规格发布的公司。Resonate 的 Dominik Tornow（@DominikTornow）宣布：团队和技术加入 Replit，帮助加强 agent 运行的基础，并称「Resonate helps agents keep their promises」。帖中链到 Resonate 网站，未披露交易条款。
背景：11 月 18 日 Builders 已报过 Replit 推出 Missions，用有预算上限的 agent swarm 去完成给定目标。这篇研究讨论的是 swarm 何时比单 agent 更强、以及组织方式，是同一产品方向上的研究结果，不是 Missions 上线的重复。Resonate 的加入是新的团队和技术动向。
实际影响：做 multi-agent 的人可以对照「公共板认领任务、少走中心协调者」和「工作是否可并行」来设计组织方式，并查看 Optimization-Bench；不要假设更强的单模型就一定更会协作，也不要假设加人就一定更快。Resonate 加入后对用户产品的具体变化，帖中尚未说明，现在不能按已经可用的新功能来理解。
